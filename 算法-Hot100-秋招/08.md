## LC11：容器能装多少水，由谁决定？

LC11「盛最多水的容器」：给你一个数组 `heights`，每个数字代表一根竖线的高度。任选两根线和底边组成一个容器，求能装水的最大面积。

```text
heights = [1, 8, 6, 2, 5, 4, 8, 3, 7]
答案 = 49
```

选下标 1 的高度 8 和下标 8 的高度 7：

```text
宽度 = 8 - 1 = 7
有效高度 = min(8, 7) = 7
面积 = 7 * 7 = 49
```

## 先把面积公式说清楚

当两根线的下标是 `left` 和 `right` 时：

```text
宽度 = right - left
有效高度 = 两根线中较短的高度
面积 = 宽度 * 有效高度
```

为什么看较短的线？水会从较短的一边流出去。左线是 8、右线是 3 时，再高的左线也帮不了忙，容器最多只能装到高度 3。

```text
面积 = (right - left) * min(heights[left], heights[right])
```

## 暴力解法为什么慢？

最直接的做法是枚举每一对线：

```text
第 0 根与后面所有线组合。
第 1 根与后面所有线组合。
第 2 根与后面所有线组合。
...
```

一共有大约 `n * (n - 1) / 2` 对，时间复杂度 `O(n^2)`。

这题的突破不是“少算一点”，而是：从最宽的两端开始后，能不能判断哪一端一定不值得保留？

## 从最宽的容器开始

先让两个指针站在最两端：

```text
left 在 0，right 在最后一个下标。
```

这时宽度最大。每一轮算一次面积后，必须缩小区间：要么 `left += 1`，要么 `right -= 1`。

关键问题是：**该移动哪一边？**

答案是：移动较短的那一边。

## 为什么移动较高的一边一定没有用？

假设当前：

```text
left 高度 = 3
right 高度 = 8
当前宽度 = 7
当前面积 = 7 * min(3, 8) = 21
```

现在如果移动右边那根较高的 8：

- 宽度一定变小，因为右端向左走了。
- 左边的 3 还在，所以新容器的有效高度最多还是 3。

也就是说：**宽度变小，有效高度不可能超过 3。** 新面积一定不可能超过当前面积 21。

因此，保留较短的 3、移动较高的 8，只会得到已经可以安全排除的组合。

反过来，移动较短的 3 虽然宽度也会变小，但有机会找到一根更高的左线，让有效高度从 3 变成更大的值，才存在超过当前面积的可能。

> 当前两端不等高时，较短的线是瓶颈。移动瓶颈才有机会提高有效高度；移动较高的线无法突破瓶颈，只会损失宽度。

这就是双指针不是“猜着移动”的原因：每一次移动都排除了一批不可能更优的组合。

## 手工走一次

`heights = [1, 8, 6, 2, 5, 4, 8, 3, 7]`。

| `left` | `right` | 两端高度 | 宽度 | 有效高度 | 当前面积 | 移动哪边 | 原因 |
|---:|---:|---|---:|---:|---:|---|---|
| 0 | 8 | 1, 7 | 8 | 1 | 8 | 左 | 1 更短 |
| 1 | 8 | 8, 7 | 7 | 7 | 49 | 右 | 7 更短 |
| 1 | 7 | 8, 3 | 6 | 3 | 18 | 右 | 3 更短 |
| 1 | 6 | 8, 8 | 5 | 8 | 40 | 任意一边 | 高度相等，移动任一边都可以 |

最大值保留为 49。

注意：算法不会枚举所有线对，却仍能保证不漏掉最优答案。因为每次移动的都是当前瓶颈，留下它与任何更窄位置组合都无法超过当前面积；只有丢掉瓶颈才值得继续寻找。

## 可直接运行的代码

```js
/**
 * 返回两根竖线与底边构成的最大盛水面积。
 *
 * @param {number[]} heights
 * @returns {number}
 */
function maxArea(heights) {
  if (!Array.isArray(heights) || heights.length < 2) {
    return 0;
  }
  if (heights.some((height) => !Number.isFinite(height) || height < 0)) {
    return 0;
  }

  let left = 0;
  let right = heights.length - 1;
  let largestArea = 0;

  while (left < right) {
    const width = right - left;
    const limitingHeight = Math.min(heights[left], heights[right]);
    largestArea = Math.max(largestArea, width * limitingHeight);

    // 只有移动较短的边，才有机会提高下一轮的有效高度。
    if (heights[left] < heights[right]) {
      left += 1;
    } else {
      right -= 1;
    }
  }

  return largestArea;
}

console.log(maxArea([1, 8, 6, 2, 5, 4, 8, 3, 7])); // 49
console.log(maxArea([1, 1])); // 1
console.log(maxArea([4, 3, 2, 1, 4])); // 16
console.log(maxArea([1])); // 0
```

## 高度相等时为什么随便移动一边？

当两边高度相同，例如：

```text
left 高度 = 8
right 高度 = 8
```

无论移动哪边，宽度都会变小，且至少丢掉了一个当前瓶颈。移动左边或右边都不会漏掉优于当前面积的组合，因此代码中任选一边即可。

上面的代码在相等时移动右边，因为 `if` 只处理左边严格更短的情况。这是一个选择，不是唯一写法。

## 和普通双重循环的区别

LC1 用 `Map` 避免反复找搭档；LC739 用栈避免反复向右找更高温度；LC11 用相向双指针避免枚举不可能更优的线对。

它们共同的目标都是减少重复工作，但理由不同：

| 题目 | 省掉了什么 | 依据 |
|---|---|---|
| LC1 | 重复查找搭档 | `Map` 可以快速查询历史数字 |
| LC739 | 重复向右扫描 | 栈中的等待者由当前更高温度统一解决 |
| LC11 | 不可能更优的线对 | 移动较高边无法提高瓶颈且会缩小宽度 |
