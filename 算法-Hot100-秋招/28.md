### 正确答案

**第 1 题：** 为什么拆分后还需要合并？

> 拆分不会让 `[8, 3]` 自动变成 `[3, 8]`。拆到 `[8]`、`[3]` 后，每个单元素组天然有序；比较两个单元素得到 `[3, 8]`，再把两个有序小组按从小到大的顺序合并，才能逐层得到完整有序数组。

**第 2 题：** 8 个元素与 16 个元素的层数。

> 8 个元素：`8 -> 4 -> 2 -> 1`，有 3 层拆分。16 个元素：`16 -> 8 -> 4 -> 2 -> 1`，有 4 层拆分。元素数量从 8 翻倍为 16，层数只增加 1，这正是 `log n` 增长慢的直观含义。

**第 3 题：** LC56 的复杂度。

> 排序阶段：约 `log n` 层，每层总共处理 `n` 个区间，所以是 `O(n log n)`。扫描阶段：从头到尾读每个区间一次，每次只做常数工作，所以是 `O(n)`。两个阶段先后发生，总时间为 `O(n log n) + O(n) = O(n log n)`；复制输入和结果数组最多各保存 `n` 个区间，空间是 `O(n)`。

## 一、题目不是“怎么跳”，而是“目前能覆盖到哪里”

LC55 给一个非负整数数组。站在下标 `i` 时，`numbers[i]` 表示最多能向右跳几步。问能否到达最后一个下标。

例如：

```text
numbers = [2, 3, 1, 1, 4]
下标      0  1  2  3  4
```

站在下标 0，数值是 2，表示可以跳到下标 1 或 2。

最直接的想法是枚举所有跳法：从 0 跳 1，再从 1 跳；或者从 0 跳 2，再从 2 跳。这样的分支会越来越多。

但题目只问“能不能到终点”，不要求给出具体跳法。于是可以把许多跳法压缩成一个信息：

```text
farthest = 到目前为止，所有可达位置中，最远能覆盖到的下标
```

它不是“当前站在哪里”，而是“已知可以到达的范围右边界”。

## 二、先手工走一遍：成功样例

对：

```text
[2, 3, 1, 1, 4]
```

从左到右扫描，并维护 `farthest`：

| 正在查看的下标 `i` | `numbers[i]` | 查看前最远可达 `farthest` | 从 i 最远能跳到 | 更新后 `farthest` |
|---|---:|---:|---:|---:|
| 0 | 2 | 0 | `0 + 2 = 2` | 2 |
| 1 | 3 | 2 | `1 + 3 = 4` | 4 |
| 2 | 1 | 4 | `2 + 1 = 3` | 4 |
| 3 | 1 | 4 | `3 + 1 = 4` | 4 |
| 4 | 4 | 4 | 已到终点 | 已成功 |

下标 1 为什么可以参与更新？因为查看它之前，`farthest = 2`，而 `1 <= 2`，说明我们确实可以跳到下标 1。

查看下标 1 后，最远可达从 2 扩大到 4，已经覆盖终点。

## 三、失败样例：什么时候可以立即返回 false？

看：

```text
[3, 2, 1, 0, 4]
```

| 正在查看的下标 `i` | `numbers[i]` | 查看前 `farthest` | 更新后 `farthest` |
|---|---:|---:|---:|
| 0 | 3 | 0 | 3 |
| 1 | 2 | 3 | 3 |
| 2 | 1 | 3 | 3 |
| 3 | 0 | 3 | 3 |
| 4 | 4 | 3 | 不能处理 |

到下标 4 时：

```text
i = 4
farthest = 3
i > farthest
```

这意味着下标 4 根本到不了。更重要的是，所有能到达的位置都在 0 到 3 之间，而这些位置能给出的最远边界一直是 3，没有任何方法跨过下标 3 的 `0`。

所以一旦出现：

```text
i > farthest
```

就可以立刻返回 `false`。继续往右看没有意义，因为那些下标本来就到不了。

## 四、贪心不变量到底是什么？

每扫描完一个可达下标 `i` 后，始终保证：

> `farthest` 是从所有已经扫描过、并且实际可达的位置出发，能够到达的最远下标。

这句话有两部分，缺一不可：

1. **只从实际可达的位置更新。** 只有 `i <= farthest` 才能使用 `numbers[i]`；否则是在拿一个根本到不了的站点继续跳，这是错误的。
2. **只保留最远边界。** 如果某种跳法只能到 3，另一种能到 5，那么“能到 5”已经包含“能到 3”的能力，保留 3 没有额外价值。

这和 LC56 有相似之处：

```text
LC56：只维护已经合并结果的最右端点。
LC55：只维护所有可达路径的最远端点。
```

两题都不是记录全部历史，而是保留“对后续判断最有用的右边界”。

## 五、为什么不需要真的决定每一步跳多远？

假设当前能到达下标 0 到 2：

```text
numbers = [2, 3, 1, 1, 4]
                 ^
```

我们不用马上决定“从 0 跳到 1 还是 2”。只要扫描所有可达位置：

```text
从 0 最远到 2
从 1 最远到 4
从 2 最远到 3
```

取其中最大值 4，就知道某条路径可以覆盖到 4。具体是哪条路径，到最后真的需要构造路径时才记录；本题只要判断能否到达，所以一个 `farthest` 足够。

这就是贪心的压缩：不枚举每条路，只保存不会输给任何其他路径的“最远覆盖范围”。

## 六、把判断过程写成四步

1. 空数组没有起点，返回 `false`；只有一个元素时已经在终点，返回 `true`。
2. 令 `farthest = 0`，表示一开始只能站在下标 0。
3. 从左到右扫描下标 `i`：如果 `i > farthest`，说明当前下标不可达，返回 `false`；否则用 `i + numbers[i]` 尝试扩大 `farthest`。
4. 扫描结束都没有遇到不可达下标，说明最后一个下标可达，返回 `true`。

可以提前成功：只要 `farthest >= numbers.length - 1`，终点已经被覆盖，不必继续扫描。

## 七、完整 JavaScript 实现

现在再把上面的四步翻译成代码：

```javascript
function canJump(numbers) {
  if (!Array.isArray(numbers)) {
    throw new TypeError('numbers 必须是数组');
  }

  if (numbers.length === 0) {
    return false;
  }

  for (const jumpLength of numbers) {
    if (!Number.isInteger(jumpLength) || jumpLength < 0) {
      throw new TypeError('numbers 中的每一项必须是非负整数');
    }
  }

  let farthest = 0;
  const lastIndex = numbers.length - 1;

  for (let index = 0; index < numbers.length; index += 1) {
    const jumpLength = numbers[index];

    if (index > farthest) {
      return false;
    }

    farthest = Math.max(farthest, index + jumpLength);

    if (farthest >= lastIndex) {
      return true;
    }
  }

  return true;
}
```

代码先用一次线性遍历校验全部输入。LeetCode 已保证输入合法时，这一步通常可以省略；这里保留它，是为了让函数不会因为提前成功而漏掉数组后方的非法值。之后的主循环必须先检查 `index > farthest`，再用当前位置更新范围；否则可能会错误使用一个实际上不可达的下标来扩大范围。

## 八、复杂度按“状态数 -> 单次工作”计算

设数组长度为 `n`。

```text
校验阶段：读取 n 个数字，每次做常数检查，O(n)。
跳跃阶段：最多查看 n 个下标，每次可达判断、加法和 max 都是 O(1)，因此 O(n)。
时间：O(n) + O(n) = O(n)。
空间：只保存 farthest 和 lastIndex 两个额外数字，O(1)。
```

即使代码中有提前返回，最坏情况仍可能扫描所有 `n` 个元素，所以时间复杂度仍写 `O(n)`。

## 九、面试时怎么说

> 我不枚举每一种跳法，而是维护 `farthest`，表示已扫描且可达的位置中能够覆盖到的最远下标。扫描到下标 `i` 时，如果 `i > farthest`，说明当前位置不可达，后续位置更不可能到达，直接返回 false。否则用 `i + numbers[i]` 更新最远覆盖范围。只要最远范围覆盖最后一个下标，就能到达终点。数组最多扫描一次，每次常数操作，所以时间是 `O(n)`，只用常数个变量，空间是 `O(1)`。
