## LC98：二叉搜索树的规则比“左小右大”更严格

二叉搜索树（BST）的规则是：

> 对任意节点，整棵左子树中的所有值都小于它；整棵右子树中的所有值都大于它。

关键词是“整棵”。它不是只要求直接左孩子小、直接右孩子大。

先看一棵合法树：

```text
      5
     / \
    2   7
   / \   \
  1   3   9
```

所有左子树值都小于 5，所有右子树值都大于 5；对子树根 2、7 也是同样的规则，所以它是 BST。

## 最常见错误：只检查“孩子和父亲”

看下面的树：

```text
      5
     / \
    1   8
       / \
      4   9
```

只看每一对父子，似乎没有问题：

- `1 < 5`
- `8 > 5`
- `4 < 8`
- `9 > 8`

但它不是 BST，因为 4 位于 5 的**右子树**中，按根节点 5 的规则，它必须大于 5。`4 < 5`，因此整棵树不合法。

> 父节点只能给你一条限制；祖先节点留下的限制也必须一直有效。

## 把“祖先限制”写成上下界

不要问“当前节点和父亲关系对不对”，改问：

> 当前节点允许落在哪个开区间里？

从根出发时，没有祖先限制：

```text
根节点 5 的允许范围：(-Infinity, Infinity)
```

走到左孩子时，它必须小于父节点 5：

```text
节点 1 的允许范围：(-Infinity, 5)
```

走到右孩子时，它必须大于父节点 5：

```text
节点 8 的允许范围：(5, Infinity)
```

重点来了：走到 8 的左孩子 4 时，4 既要小于 8，也仍然必须大于 5：

```text
节点 4 的允许范围：(5, 8)
4 不在这个范围内，因此返回 false。
```

这就是递归函数真正负责的事情：

```text
validate(node, lowerBound, upperBound)
检查以 node 为根的整棵子树，是否所有节点都落在 (lowerBound, upperBound) 内。
```

## 递归时，哪一条边界要更新？

假设当前节点值为 `node.val`，它本身已在 `(lowerBound, upperBound)` 内。

| 去哪里 | 新的允许范围 | 原因 |
|---|---|---|
| 左子树 | `(lowerBound, node.val)` | 左子树所有节点必须小于当前节点；祖先下界仍保留 |
| 右子树 | `(node.val, upperBound)` | 右子树所有节点必须大于当前节点；祖先上界仍保留 |

你不需要记两段近似代码，只要记住一句：

> 向左走，收紧上界；向右走，收紧下界。另一侧祖先留下的限制绝不能丢。

## 空节点为什么返回 `true`？

递归检查的是“这棵子树是否违法”。空树里没有任何节点能违反规则，所以它是合法的：

```text
空子树：true
当前节点越界：false
当前节点合法：左子树合法 并且 右子树合法
```

这三个判断就是整道题的递归骨架。

## 可直接运行的代码

LeetCode 会提供 `TreeNode`。下面的定义仅用于本地运行。

```js
class TreeNode {
  constructor(value, left = null, right = null) {
    this.val = value;
    this.left = left;
    this.right = right;
  }
}

/**
 * 判断一棵二叉树是否满足严格的二叉搜索树规则。
 *
 * @param {TreeNode | null} root
 * @returns {boolean}
 */
function isValidBST(root) {
  return validate(root, -Infinity, Infinity);
}

/**
 * 验证 node 子树中的每个节点都位于开区间 (lowerBound, upperBound) 内。
 *
 * @param {TreeNode | null | undefined} node
 * @param {number} lowerBound
 * @param {number} upperBound
 * @returns {boolean}
 */
function validate(node, lowerBound, upperBound) {
  if (node === null || node === undefined) {
    return true;
  }

  if (typeof node !== 'object' || !Number.isFinite(node.val)) {
    return false;
  }

  if (node.val <= lowerBound || node.val >= upperBound) {
    return false;
  }

  // 左子树继承下界并收紧上界；右子树继承上界并收紧下界。
  return (
    validate(node.left, lowerBound, node.val) &&
    validate(node.right, node.val, upperBound)
  );
}

const validTree = new TreeNode(
  5,
  new TreeNode(2, new TreeNode(1), new TreeNode(3)),
  new TreeNode(7, null, new TreeNode(9)),
);

const invalidTree = new TreeNode(
  5,
  new TreeNode(1),
  new TreeNode(8, new TreeNode(4), new TreeNode(9)),
);

console.log(isValidBST(validTree)); // true
console.log(isValidBST(invalidTree)); // false：4 在 5 的右子树，却小于 5
console.log(isValidBST(new TreeNode(2, new TreeNode(2), new TreeNode(3)))); // false：BST 不允许重复值
console.log(isValidBST(null)); // true
```

## 为什么重复值会失败？

LC98 使用的是严格 BST：左边必须 `<`，右边必须 `>`，不允许相等。

因此判断越界时必须使用：

```js
node.val <= lowerBound || node.val >= upperBound
```

如果你误写成 `<` 和 `>`，等于边界的节点会被放过，重复值树会被错误判为合法。

## 另一种思路：中序遍历

BST 的中序遍历结果必须严格递增。例如合法树中序是：

```text
[1, 2, 3, 5, 7, 9]
```

所以也可以中序遍历，并检查当前值是否大于上一个访问值。项目中的 [LC98.验证二叉搜索树.js](D:/Project/LeetCode/剑指offer/LC98.验证二叉搜索树.js) 就是这条路线。

两种方法都正确；本文优先讲上下界，因为它直接揭示了“祖先约束不能丢”这个更可迁移的递归模型。面试时能讲出这一点，比只背中序递增更稳。

## 复杂度和面试表达

- 时间复杂度：`O(n)`，每个节点最多检查一次。
- 额外空间：`O(h)`，递归调用栈高度为树高 `h`；极端退化树时是 `O(n)`。

面试表达：

> 我递归维护每个节点允许的开区间。根节点范围是负无穷到正无穷；进入左子树时把当前值作为上界，进入右子树时把当前值作为下界，同时保留祖先传下来的另一侧边界。若节点不在范围内立即返回 false。这样能检查祖先约束，避免只比较父子节点的错误。
