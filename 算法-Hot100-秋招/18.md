### 你的回答评估

- 第 1 题：⚠️ 基本正确。你正确抓住了叶子位于最后一层，叶子数是 `2^4 = 16`。需要补充的是：从根的第 0 层开始，深度依次为 `0、1、2、3、4`，因此共有 **5 层**，不是 4 层。
- 第 2 题：⚠️ 方向正确，但“只是一层递归”不准确。只计算数量时，可以让每个递归深度只调用下一深度一次，形成一条长度为 `n` 的调用链；这叫“每层一个调用”，不是“只有一层递归”。
- 第 3 题：✅ 结论正确。直接使用 `2^n` 不需要遍历；保留枚举所有选/不选分支的原代码则仍然会遍历整棵决策树。

### 正确答案

**第 1 题：** `numbers = [1, 2, 3, 4]` 的层数、叶子数和子集数。

> 根调用还没有决定任何数字，算第 0 层。决定 1 个、2 个、3 个、4 个数字后，分别是第 1、2、3、4 层，所以共有 `0、1、2、3、4` 五层。最后一层每个数字都已经做完“选或不选”的决定，共有 `2 * 2 * 2 * 2 = 2^4 = 16` 个叶子，也就是 16 个子集。

**第 2 题：** 为什么只计算数量时可以更低？

> 原来的代码需要分别展开“不选当前数字”和“选当前数字”两条分支，因此会产生约 `2^n` 次调用。若两个分支的数量一定相同，可以只计算一次下一层，再乘以 2：`count(index) = 2 * count(index + 1)`。这样每个深度只有一个递归调用，调用链长度为 `n`，时间和递归栈空间都是 `O(n)`。这不是没有递归，而是不再分叉。

**第 3 题：** 只返回数量时的两种实现。

> 直接返回 `2^n` 是 `O(1)` 时间、`O(1)` 空间；使用 `count(index) = 2 * count(index + 1)` 是 `O(n)` 时间、`O(n)` 栈空间；保留原枚举代码则是 `O(2^n)` 时间。复杂度取决于代码到底有没有展开分支，而不是函数名字里是否出现 `recursive`。

## LC200：一块岛屿应该只统计一次

LC200「岛屿数量」给一个由 `'1'`（陆地）和 `'0'`（水）组成的二维网格，水平或垂直相邻的陆地属于同一座岛，返回岛屿数量。

```text
grid = [
  ["1", "1", "0", "0"],
  ["1", "0", "0", "1"],
  ["0", "0", "1", "1"]
]

答案：3
```

左上角的三个 `'1'` 是一座岛；右上角孤立的 `'1'` 是第二座；右下角相连的两个 `'1'` 是第三座。

这道题的关键不是“找到一个 1 就加一”，而是：

> 找到一块尚未处理的陆地后，把与它连通的整座岛全部消耗掉；之后再遇到的格子就不会重复统计这座岛。

## 外层扫描负责“发现新岛屿”

用双层循环扫描每个格子：

```text
如果当前格子是水：跳过
如果当前格子是未消耗的陆地：岛屿数量 + 1，并 DFS 消耗整座岛
```

为什么只在发现入口时加一？因为同一座岛的其他陆地会在 DFS 中被标记，外层循环再次走到它们时已经不是未处理状态。

## DFS 负责“消耗一整座岛”

从一个陆地格子出发，只向四个方向走：上、下、左、右。

```text
dfs(row, column)
1. 越界：返回
2. 是水或已访问：返回
3. 标记为已访问
4. 递归访问四个相邻格子
```

这里的递归函数含义很具体：

> `dfs(row, column)` 会把从这个陆地格子出发能够到达的整块连通陆地全部标记为已访问。

## 为什么可以直接把 `'1'` 改成 `'0'`？

如果允许修改输入网格，访问到陆地时可以直接写成 `'0'`。这相当于告诉后续扫描：

```text
这块陆地已经被某座岛消耗过，不要再次计数。
```

不想修改输入时，也可以额外使用 `visited[row][column]`。两者的核心都是同一个状态：**每个陆地格子只能被处理一次**。

## 手工追踪一次

从上面的网格开始扫描：

1. `(0, 0)` 是未访问陆地，答案从 0 变 1；DFS 消耗 `(0,0)`、`(0,1)`、`(1,0)`。
2. 外层继续扫描时，这三个位置都已变成水，跳过。
3. `(1, 3)` 是新的未访问陆地，答案变 2；它没有相邻陆地，DFS 只处理自己。
4. `(2, 2)` 是新的未访问陆地，答案变 3；DFS 消耗 `(2,2)` 和 `(2,3)`。

最终得到 3。注意：DFS 内部访问同一块岛时不会增加答案，增加答案的动作只在外层“发现新入口”时发生。

## 可直接运行的代码

下面选择“原地标记”方案：访问陆地后直接改为水，因此不需要额外的 `visited` 二维数组。

```js
/**
 * 返回网格中的岛屿数量。
 * 输入网格会被原地修改：已访问的陆地会改成水。
 *
 * @param {string[][]} grid
 * @returns {number}
 */
function numIslands(grid) {
  if (!Array.isArray(grid) || grid.length === 0) {
    return 0;
  }

  const columnCount = Array.isArray(grid[0]) ? grid[0].length : 0;
  if (columnCount === 0) {
    return 0;
  }

  for (const row of grid) {
    if (!Array.isArray(row) || row.length !== columnCount) {
      return 0;
    }
    if (row.some((cell) => cell !== '0' && cell !== '1')) {
      return 0;
    }
  }

  const rowCount = grid.length;
  let islandCount = 0;

  function dfs(row, column) {
    if (
      row < 0 ||
      row >= rowCount ||
      column < 0 ||
      column >= columnCount ||
      grid[row][column] !== '1'
    ) {
      return;
    }

    // 先标记再递归，避免相邻格子互相重复进入。
    grid[row][column] = '0';
    dfs(row - 1, column);
    dfs(row + 1, column);
    dfs(row, column - 1);
    dfs(row, column + 1);
  }

  for (let row = 0; row < rowCount; row += 1) {
    for (let column = 0; column < columnCount; column += 1) {
      if (grid[row][column] !== '1') {
        continue;
      }

      islandCount += 1;
      dfs(row, column);
    }
  }

  return islandCount;
}

console.log(
  numIslands([
    ['1', '1', '0', '0'],
    ['1', '0', '0', '1'],
    ['0', '0', '1', '1'],
  ]),
); // 3
console.log(numIslands([['0', '0'], ['0', '0']])); // 0
console.log(numIslands([['1']])); // 1
console.log(numIslands([])); // 0
```

## 复杂度：先定义两个输入规模

二维网格不能只写一个 `n`。设：

```text
m = 行数
n = 列数
格子总数 = m * n
```

之后所有复杂度都围绕 `m * n` 计算。

## 第一步：外层双循环执行多少次？

外层循环有 `m` 次，每一行的内层循环有 `n` 次：

```text
m 行 * 每行 n 个格子 = m * n 次
```

每次只做常数级判断，所以外层扫描成本是 `O(m * n)`。

## 第二步：DFS 会不会让每个格子重复很多次？

看起来每个陆地格子会递归四个方向，好像可能是 `4 * m * n`，甚至指数级。但关键是：

> 每个陆地格子第一次进入 DFS 后立刻改成 `'0'`，以后再次从邻居走到它时，第一层判断就返回。

因此每个格子真正执行“标记并继续递归”的主体最多一次。每个格子最多检查四个方向，四是常数：

```text
最多 m * n 个格子 * 每格最多 4 个方向
= 4 * m * n
= O(m * n)
```

DFS 的总成本也是 `O(m * n)`，而不是“每个格子四次递归所以 `O(4^(m*n))`”。分支数只有在同一状态可能无限重复展开、且没有访问标记时才会造成指数爆炸；本题的原地标记阻止了重复展开。

## 第三步：合并外层扫描和 DFS

代码先后执行两部分：

```text
外层扫描：O(m * n)
所有 DFS：O(m * n)
总时间：O(m * n) + O(m * n) = O(m * n)
```

这里是相加，不是相乘，因为 DFS 并不是每个外层格子都完整执行一遍；所有 DFS 合起来最多消耗每个格子一次。即使写成两个同阶项，保留一个即可。

## 第四步：空间复杂度要说明原地修改的代价

本文没有 `visited` 数组，但 DFS 有递归栈：

- 最宽的岛可能覆盖很多格子，但递归调用链的长度取决于 DFS 深度。
- 在最坏情况下，岛屿可能退化成一条蛇形路径，递归深度达到 `m * n`。
- 因此额外空间（递归栈）最坏是 `O(m * n)`。
- 网格本身被修改，不把输入网格重复计入额外空间。

如果改用显式队列做 BFS，最坏情况下队列也可能保存 `O(m * n)` 个格子；时间复杂度仍是 `O(m * n)`。

## 和 LC78 的复杂度放在一起对比

| 题目 | 递归结构 | 是否有重复展开 | 时间复杂度 |
|---|---|---|---|
| LC78 子集 | 每层固定分成选/不选两条分支 | 每条决策路径都不同，必须枚举 | `O(n * 2^n)`（含输出复制） |
| LC200 岛屿 | 从陆地向四邻域扩散 | 已访问格子立即停止重复进入 | `O(m * n)` |

这张表揭示一个重要判断：

> 看到递归或 DFS 不能直接写指数复杂度；先问“一个状态会不会被重复处理”。有访问标记且每个状态只消耗一次时，通常可以按状态总数求和。
