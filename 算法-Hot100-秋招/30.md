### 你的回答评估

- 第 1 题：✅ 正确。0 的前一个数字 -1 不存在，因此 0 是起点；从 0 能连续数到 8，长度为 9。
- 第 2 题：⚠️ 结论正确，但计算式要修正。删除起点判断后，1 会检查 2、3、4，2 会检查 3、4，3 会检查 4；总工作量是 `n + (n - 1) + ... + 1` 的**相加**，不是相乘。该和约为 `n² / 2`，所以是 `O(n²)`。
- 第 3 题：✅ 正确。建 Set 为 `O(n)`，外层检查 `k` 个不同数字，所有内层扩展合计最多再处理 `k` 个不同数字；它们是先后或总量合计，不是每个外层都跑完整个内层。因为 `k <= n`，总时间为 `O(n)`。

### 正确答案

**第 1 题：** 最长序列的起点。

> 对 `[0, 3, 7, 2, 5, 8, 4, 6, 0, 1]`，只有 0 满足 `0 - 1` 不在 Set 中；从 0 向右检查 1、2、3、4、5、6、7、8，得到长度 9。

**第 2 题：** 删除起点判断后的重复工作。

> 对 `[1, 2, 3, 4]`，从 1 向右查 2、3、4、5；从 2 向右查 3、4、5；从 3 向右查 4、5；从 4 向右查 5。随着序列变长，工作量是 `n + (n - 1) + ... + 1`，约为 `n(n + 1) / 2`，即 `O(n²)`。

**第 3 题：** 为什么嵌套循环仍是 `O(n)`？

> 外层会检查每个不同数字一次；内层只会从每段序列的唯一起点出发。一个数字不会既被某段起点向右计数，又重新作为另一段起点向右计数，所以所有内层循环合在一起至多沿不同数字走 k 次。总工作是 `O(n) + O(k) + O(k)`，而 `k <= n`，因此为 `O(n)`。

## 一、先看清轮转到底要什么结果

LC189 给一个数组和整数 `k`，要求把数组向右轮转 `k` 步，并且必须直接修改原数组。

```text
numbers = [1, 2, 3, 4, 5, 6, 7]
k = 3

结果 = [5, 6, 7, 1, 2, 3, 4]
```

把它理解成“最后 k 个元素整体搬到前面”：

```text
[1, 2, 3, 4 | 5, 6, 7]
                 末尾 3 个搬到前面
=> [5, 6, 7 | 1, 2, 3, 4]
```

如果创建新数组，把每个元素算出新下标，当然能做；但题目要求原地修改，因此我们要利用已有数组本身完成这次搬运。

## 二、先处理一个会改变结果的边界：k 可能很大

数组长度是 7 时，向右轮转 7 次，数组会回到原样：

```text
[1, 2, 3, 4, 5, 6, 7]
轮转 7 次
=> [1, 2, 3, 4, 5, 6, 7]
```

轮转 10 次和轮转 3 次结果相同：

```text
10 % 7 = 3
```

因此真正需要轮转的步数是：

```text
effectiveSteps = k % numbers.length
```

空数组不能做取余，所以它必须先返回。

## 三、三次翻转：先看结果，不要先背口诀

仍然用：

```text
[1, 2, 3, 4, 5, 6, 7]
k = 3
```

目标是：

```text
[5, 6, 7, 1, 2, 3, 4]
```

### 第一次：翻转整个数组

```text
[1, 2, 3, 4, 5, 6, 7]
=> [7, 6, 5, 4, 3, 2, 1]
```

原来的“末尾 3 个”现在已经跑到了前面，但顺序反了：

```text
[7, 6, 5 | 4, 3, 2, 1]
```

### 第二次：翻转前 k 个元素

```text
[7, 6, 5 | 4, 3, 2, 1]
=> [5, 6, 7 | 4, 3, 2, 1]
```

前半部分已经变成目标中的 `[5, 6, 7]`。

### 第三次：翻转剩余元素

```text
[5, 6, 7 | 4, 3, 2, 1]
=> [5, 6, 7 | 1, 2, 3, 4]
```

得到目标结果。

你不需要记住“翻转三次”这个表面步骤。真正的原因是：

```text
整体翻转：把末尾块搬到前面，但两块内部顺序都反了。
翻转前块：修复原末尾块的内部顺序。
翻转后块：修复原前面块的内部顺序。
```

## 四、相向双指针只负责一件事：翻转一个闭区间

写一个小工具：给定 `left` 和 `right`，交换两端元素，然后两端向中间靠近。

例如翻转下标 1 到 5：

```text
[0, 1, 2, 3, 4, 5, 6]
    L           R
交换 1 和 5

[0, 5, 2, 3, 4, 1, 6]
       L     R
交换 2 和 4

[0, 5, 4, 3, 2, 1, 6]
          L R
停止
```

停止条件是 `left >= right`。当两指针相遇或交错时，区间已经翻转完毕。

## 五、把三次翻转变成算法步骤

1. 校验输入是数组、`k` 是非负整数；空数组直接结束。
2. 计算 `effectiveSteps = k % length`。
3. 翻转整个区间 `[0, length - 1]`。
4. 翻转前段 `[0, effectiveSteps - 1]`。
5. 翻转后段 `[effectiveSteps, length - 1]`。

当 `effectiveSteps = 0` 时，第 4 步的右端点是 -1。更清楚的写法是直接返回，因为轮转 0 步不需要修改数组。

## 七、完整 JavaScript 实现

```javascript
function rotate(numbers, stepCount) {
  if (!Array.isArray(numbers)) {
    throw new TypeError('numbers 必须是数组');
  }

  if (!Number.isSafeInteger(stepCount) || stepCount < 0) {
    throw new RangeError('stepCount 必须是非负安全整数');
  }

  for (const value of numbers) {
    if (!Number.isFinite(value)) {
      throw new TypeError('numbers 中的每一项必须是有限数字');
    }
  }

  if (numbers.length === 0) {
    return;
  }

  const effectiveSteps = stepCount % numbers.length;
  if (effectiveSteps === 0) {
    return;
  }

  reverseRange(numbers, 0, numbers.length - 1);
  reverseRange(numbers, 0, effectiveSteps - 1);
  reverseRange(numbers, effectiveSteps, numbers.length - 1);
}

function reverseRange(numbers, left, right) {
  while (left < right) {
    [numbers[left], numbers[right]] = [numbers[right], numbers[left]];
    left += 1;
    right -= 1;
  }
}
```

本题要求原地修改，所以 `rotate` 没有返回新数组；调用后直接观察传入的 `numbers`。

## 八、复杂度：三次循环为什么不是 `O(3n)`？

设数组长度为 `n`。

三次翻转处理的元素数量分别最多为：

```text
第一次：n 个元素。
第二次：k 个元素。
第三次：n - k 个元素。
```

总处理量：

```text
n + k + (n - k) = 2n
```

每次交换和指针移动都是常数工作，所以：

```text
时间复杂度：O(2n) = O(n)
辅助空间：O(1)
```

`2` 是常数，不会随着 n 增长，因此大 O 中省略。

## 九、面试时怎么说

> 题目要求原地轮转，我先将 k 对数组长度取余，避免无效的整圈轮转。然后翻转整个数组，使原末尾的 k 个元素移动到前面，但两段内部顺序都会反转；再分别翻转前 k 个和后 n-k 个元素，恢复各自顺序。每次翻转都用相向双指针原地交换。三次翻转处理的总元素数量是 n + k + (n-k)，即 O(n)，只使用常数额外变量，空间 O(1)。
