**第 1 题：** 排序数组 `[-2, -1, -1, 0, 1, 2]`，固定下标 1 的 -1：

```text
left = 2，right = 5，和为 -1 + -1 + 2 = 0，记录 [-1, -1, 2]。
```

## LC19：删除节点前，先找到它的前一个节点

LC19「删除链表的倒数第 N 个结点」：给你单链表头节点 `head` 和正整数 `n`，删除倒数第 `n` 个节点，返回新的头节点。

```text
链表：1 -> 2 -> 3 -> 4 -> 5
n = 2
结果：1 -> 2 -> 3 -> 5
```

倒数第 2 个是节点 4。单链表无法直接向左走，因此最关键的不是“找到节点 4”，而是找到它的前一个节点 3：

```text
3.next = 3.next.next
```

这行代码让 3 直接指向 5，节点 4 就从链表中断开了。

## 先看最容易卡住的边界：删除头节点

如果链表是：

```text
1 -> 2 -> 3
n = 3
```

要删的是头节点 1。头节点没有前一个真实节点，若代码每次都假设“前一个节点存在”，就需要写特殊分支。

虚拟头结点就是专门用来消除这个特殊分支的：

```text
dummy -> 1 -> 2 -> 3
```

`dummy` 不是题目原链表里的真实数据节点，只是临时站在头节点前面。无论删除中间节点还是头节点，都统一写：

```text
previous.next = previous.next.next
```

删除头节点时，`previous` 恰好是 `dummy`。

最后返回：

```js
return dummy.next;
```

因为原头节点可能已经被删掉，新的头节点只能从 `dummy.next` 取得。

## 不要先数长度：让两个指针保持固定距离

一种可行方法是先遍历一次链表得到长度，再遍历第二次到“倒数第 n 个的前一个节点”。时间仍是 `O(n)`，但需要两次走链表。

更常用的办法是快慢双指针：

```text
slow 和 fast 都从 dummy 出发。
先让 fast 向前走 n 步。
之后 slow 和 fast 一起每次走一步。
```

这样 `fast` 始终比 `slow` 快 n 个节点。

当 `fast` 走到最后一个真实节点时，`slow` 就刚好在“倒数第 n 个节点的前一个节点”。

## 用链表 `1 -> 2 -> 3 -> 4 -> 5`、n = 2 手工走一遍

开始：

```text
dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> null
slow、fast 都在 dummy
```

先让 `fast` 走 2 步：

```text
第 1 步：fast 到 1
第 2 步：fast 到 2
```

现在 `fast` 和 `slow` 相差 2 步。接下来只要 `fast.next` 不为空，两者一起移动：

| 一起移动后 | `slow` 所在节点 | `fast` 所在节点 |
|---|---:|---:|
| 第 1 次 | 1 | 3 |
| 第 2 次 | 2 | 4 |
| 第 3 次 | 3 | 5 |

此时 `fast.next` 是 `null`，停止。`slow` 在 3，`slow.next` 正是要删除的 4：

```text
slow.next = slow.next.next
3.next = 5
```

## 为什么循环条件是 `fast.next`，不是 `fast`？

我们想让 `slow` 最终停在待删除节点的**前一个**节点。

当 `fast` 已经在最后一个节点时，`fast.next` 是 `null`，应该停止；此时 `slow` 恰好在前一个节点。

如果写成 `while (fast)`，会多走一步：`slow` 会走到要删除的节点本身。这样再写 `slow.next = slow.next.next`，删掉的就变成下一个节点，位置错一位。

## 可直接运行的代码

下面代码包含本地测试辅助函数。提交 LeetCode 时，只保留 `removeNthFromEnd` 函数即可，平台会提供 `ListNode`。

```js
function ListNode(value, next = null) {
  this.val = value;
  this.next = next;
}

/**
 * 删除倒数第 n 个节点。
 * n 不合法时返回原链表；LeetCode 题目通常保证 n 合法。
 *
 * @param {ListNode | null} head
 * @param {number} n
 * @returns {ListNode | null}
 */
function removeNthFromEnd(head, n) {
  if (!Number.isInteger(n) || n <= 0) {
    return head;
  }

  const dummy = new ListNode(0, head);
  let slow = dummy;
  let fast = dummy;

  // fast 先走 n 步，建立它与 slow 的固定间距。
  for (let step = 0; step < n; step += 1) {
    if (fast.next === null) {
      return head;
    }
    fast = fast.next;
  }

  // fast 到最后一个真实节点时，slow 位于待删节点的前一个节点。
  while (fast.next !== null) {
    slow = slow.next;
    fast = fast.next;
  }

  slow.next = slow.next.next;
  return dummy.next;
}

function arrayToList(values) {
  const dummy = new ListNode(0);
  let tail = dummy;

  for (const value of values) {
    tail.next = new ListNode(value);
    tail = tail.next;
  }
  return dummy.next;
}

function listToArray(head) {
  const values = [];
  let current = head;

  while (current !== null) {
    values.push(current.val);
    current = current.next;
  }
  return values;
}

console.log(listToArray(removeNthFromEnd(arrayToList([1, 2, 3, 4, 5]), 2)));
// [1, 2, 3, 5]
console.log(listToArray(removeNthFromEnd(arrayToList([1]), 1))); // []
console.log(listToArray(removeNthFromEnd(arrayToList([1, 2]), 2))); // [2]
console.log(listToArray(removeNthFromEnd(arrayToList([1, 2]), 3))); // [1, 2]
```

## `n = 链表长度` 时为什么能删除头节点？

例如 `1 -> 2`、`n = 2`：

```text
fast 从 dummy 走 2 步后到 2。
fast.next 已经是 null，因此一起移动的循环不执行。
slow 仍停在 dummy。
slow.next 是原头节点 1，执行 dummy.next = 1.next。
返回 dummy.next，也就是 2。
```

虚拟头结点让“删头节点”与“删中间节点”使用完全相同的删除语句。

## 复杂度

`fast` 最多走链表长度步，`slow` 最多也走链表长度步：

```text
时间复杂度：O(length)
额外空间：O(1)
```

这里的 `dummy`、`slow`、`fast` 都只是几个固定数量的节点引用，不会随着链表变长而增加。
