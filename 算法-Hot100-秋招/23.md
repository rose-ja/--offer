## LC300：子序列可以跳过元素，但不能改变原顺序

给定整数数组，找出**最长严格递增子序列**的长度。

```text
numbers = [10, 9, 2, 5, 3, 7, 101, 18]
答案 = 4

例如子序列 [2, 3, 7, 101] 长度为 4。
```

先区分两个词：

```text
子数组：必须连续。
子序列：可以跳过中间元素，但剩下元素的先后顺序不能改变。
```

所以 `[2, 3, 7, 101]` 合法，因为它们在原数组中出现顺序不变；`[3, 2, 7]` 不合法，因为 3 在 2 的后面，不能把它调到 2 前面。

## 先别问“前 i 个数的答案”，先问一个更小的问题

直接问“前 i 个数中最长多长”会让你不知道最后一个数是谁，也就不知道如何把当前数字接进去。

先固定结尾：

> `lengths[i]`：必须以 `numbers[i]` 结尾的最长严格递增子序列长度。

“必须以 i 结尾”非常重要。举例：

```text
numbers = [3, 1, 2, 5, 4]
```

`lengths[3]` 问的是“最后一个数必须是 5，最长是多少”，答案是 3，例如 `[1, 2, 5]`。

它**不问**“前四个数随便选时最长是多少”，虽然此例中数值碰巧也都是 3。固定结尾，是为了能明确判断谁可以接在当前数前面。

## 手工做一遍：当前数字前面，谁能接上来？

继续使用：

```text
下标：       0  1  2  3  4
numbers：    [3, 1, 2, 5, 4]
```

先看下标 0，数是 3：前面没有数，所以只能自己单独组成 `[3]`。

```text
lengths[0] = 1
```

下标 1，数是 1：前面只有 3，但 `3 < 1` 不成立，不能把 3 接到 1 前面。所以它也只能自己开始。

```text
lengths[1] = 1
```

下标 2，数是 2：检查前面的每个数：

```text
3 < 2：不成立，3 不能接在 2 前面。
1 < 2：成立，可以把“以 1 结尾”的 [1] 后面接 2，得到 [1, 2]。
```

因此：

```text
lengths[2] = lengths[1] + 1 = 2
```

下标 3，数是 5：所有比 5 小的前面数字都可以作为前驱：

```text
3 < 5：可以得到长度 lengths[0] + 1 = 2
1 < 5：可以得到长度 lengths[1] + 1 = 2
2 < 5：可以得到长度 lengths[2] + 1 = 3
```

同一个当前位置可能有多个可接前驱。我们要的是最长，所以取最大：

```text
lengths[3] = 3，对应 [1, 2, 5]
```

下标 4，数是 4：

```text
3 < 4：候选长度 2
1 < 4：候选长度 2
2 < 4：候选长度 3
5 < 4：不成立，不能接
```

所以：

```text
lengths[4] = 3，对应 [1, 2, 4]
```

## 从手工过程得到转移式

当前计算 `lengths[i]` 时，要枚举所有在它前面的下标 `j`：

```text
0 <= j < i
```

只有当 `numbers[j] < numbers[i]` 时，才能把“以 j 结尾的递增子序列”后面接上 `numbers[i]`：

```text
候选长度 = lengths[j] + 1
```

所有合法前驱里取最长：

```text
lengths[i] = max(lengths[j] + 1)
             其中 j < i 且 numbers[j] < numbers[i]
```

如果一个合法前驱也没有呢？当前数字自己单独就是长度 1 的递增子序列，因此每个 `lengths[i]` 的初始值都应该是 1。

```text
lengths = [1, 1, 1, ..., 1]
```

## 为什么最终答案不是 `lengths[n - 1]`？

最长递增子序列可能结束在任何位置，不一定结束在数组最后一个数。

仍看：

```text
[10, 9, 2, 5, 3, 7, 101, 18]
```

最长的一个序列以 101 结尾，长度为 4；但最后一个数字 18 也能组成长度为 4 的序列。更简单的反例是：

```text
[1, 2, 3, 0]
lengths = [1, 2, 3, 1]
```

数组最后的 `lengths[3]` 是 1，但真正答案是 3。因此最终答案是：

```text
max(lengths[0], lengths[1], ..., lengths[n - 1])
```

## 把手工过程整理成一张 DP 表

对 `[3, 1, 2, 5, 4]`：

| i | 当前数 `numbers[i]` | 可接前驱 j（值） | 可得候选长度 | `lengths[i]` |
|---:|---:|---|---|---:|
| 0 | 3 | 无 | 只能自己组成序列 | 1 |
| 1 | 1 | 无 | 只能自己组成序列 | 1 |
| 2 | 2 | 1（1） | `1 + 1 = 2` | 2 |
| 3 | 5 | 0（3）、1（1）、2（2） | `2、2、3` | 3 |
| 4 | 4 | 0（3）、1（1）、2（2） | `2、2、3` | 3 |

最终从 `[1, 1, 2, 3, 3]` 中取最大值，答案是 3。

## 到这里才看代码：两层循环分别在做什么？

```text
外层 i：决定“现在要计算哪个结尾”。
内层 j：依次检查当前数前面的每一个候选前驱。
```

第一次看代码时，先只看下面两句：

```js
if (numbers[previous] < numbers[current]) {
  lengths[current] = Math.max(lengths[current], lengths[previous] + 1);
}
```

它直接翻译了手工过程：若前一个数更小，就可以接；接上后，看看是否比当前已知的最长长度更好。

## 可直接运行的代码

这是最适合建立 DP 状态直觉的 `O(n^2)` 写法。LC300 还有更快的 `O(n log n)` 解法，但它维护的数组含义不同；在没有先掌握状态定义前，不需要提前学习它。

```js
/**
 * 返回严格递增子序列的最大长度。
 * 子序列允许跳过元素，但不能改变元素在原数组中的相对顺序。
 *
 * @param {number[]} numbers
 * @returns {number}
 */
function lengthOfLIS(numbers) {
  if (!Array.isArray(numbers) || numbers.some((number) => !Number.isFinite(number))) {
    return 0;
  }
  if (numbers.length === 0) {
    return 0;
  }

  // lengths[i]：必须以 numbers[i] 结尾的最长严格递增子序列长度。
  const lengths = new Array(numbers.length).fill(1);
  let longestLength = 1;

  for (let current = 0; current < numbers.length; current += 1) {
    for (let previous = 0; previous < current; previous += 1) {
      if (numbers[previous] >= numbers[current]) {
        continue;
      }

      const candidateLength = lengths[previous] + 1;
      lengths[current] = Math.max(lengths[current], candidateLength);
    }

    longestLength = Math.max(longestLength, lengths[current]);
  }

  return longestLength;
}

console.log(lengthOfLIS([10, 9, 2, 5, 3, 7, 101, 18])); // 4
console.log(lengthOfLIS([3, 1, 2, 5, 4])); // 3
console.log(lengthOfLIS([7, 7, 7])); // 1
console.log(lengthOfLIS([])); // 0
console.log(lengthOfLIS([1, Number.NaN])); // 0：本地非法输入
```

## 代码逐段对应手工表

| 代码 | 对应的手工含义 |
|---|---|
| `fill(1)` | 每个数至少能单独形成长度 1 的子序列 |
| `current` 外层循环 | 现在要求“以哪个位置结尾”的答案 |
| `previous < current` | 只能从当前数前面的元素接过来，顺序不能倒过来 |
| `numbers[previous] < numbers[current]` | 前驱数必须更小，接上后才严格递增 |
| `lengths[previous] + 1` | 在原有序列末尾接上当前数 |
| `Math.max(...)` | 当前数可能有多个可接前驱，保留最长那条 |
| `longestLength` | 真正答案可能在任何位置结尾，持续记录全局最大值 |

## 复杂度：两层循环不是直接背 `O(n^2)`

设：

```text
n = numbers.length
```

### 第一步：外层执行多少次？

`current` 从 0 到 n-1：

```text
n 次
```

### 第二步：每次内层执行多少次？

内层不是每次都跑 n 次：

```text
current = 0：previous 没有可取值，0 次
current = 1：previous 取 0，1 次
current = 2：previous 取 0、1，2 次
...
current = n - 1：previous 取 0 到 n - 2，n - 1 次
```

总比较次数是：

```text
0 + 1 + 2 + ... + (n - 1)
= n * (n - 1) / 2
```

除以 2 是常数，因此这个量随 n 增长的主要部分是 `n^2`：

```text
O(n * (n - 1) / 2) = O(n^2)
```

### 第三步：每次比较做多少工作？

每次内层循环最多做：比较两个数、计算候选长度、比较两个长度、写入一个数组位置。都是固定数量的操作：

```text
每次 = O(1)
总次数 = O(n^2)
总时间 = O(n^2) * O(1) = O(n^2)
```

数组初始化是 `O(n)`，和 `O(n^2)` 相加时保留增长更快的项：

```text
O(n) + O(n^2) = O(n^2)
```

### 空间复杂度

`lengths` 保存 n 个位置，其他变量数量固定：

```text
辅助空间 = O(n)
```

## LC198 和 LC300 的状态差异

| 题目 | 状态必须额外限定什么？ | 为什么 |
|---|---|---|
| LC198 | 前 i 间房 | 当前房是否偷，只依赖前两段最优金额 |
| LC300 | 必须以第 i 个数结尾 | 是否能接当前数，取决于前驱数的值是否更小 |

> 当“当前元素能否接到已有答案后面”取决于它和前面元素的关系时，常常要把状态限定为“以当前位置结尾”。否则你只知道全局最优值，却不知道它的最后一个元素能不能接当前数。

## 面试时怎么说

> 我定义 `lengths[i]` 为必须以 `numbers[i]` 结尾的最长严格递增子序列长度。每个数单独都能构成长度 1。计算 i 时，枚举所有前驱 j < i；只有 `numbers[j] < numbers[i]` 时，才能在以 j 结尾的序列后接上 i，候选长度为 `lengths[j] + 1`，取最大的候选。最终答案取所有 `lengths[i]` 的最大值。两层枚举总比较次数为 `0 + 1 + ... + n-1`，所以时间 `O(n^2)`，状态数组空间 `O(n)`。
