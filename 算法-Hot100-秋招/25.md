### 你的回答评估

- 第 1 题：✅ 正确。`common[1][1] = 1`、`common[1][2] = 1`、`common[2][1] = 1`、`common[2][2] = 1`、`common[3][1] = 1`、`common[3][2] = 2`。最后一个格子比较的是 `c` 与 `c`，所以沿左上角 `common[2][1]` 加 1。
- 第 2 题：✅ 正确。最后字符不同，只能忽略第一个字符串的最后字符，或忽略第二个字符串的最后字符；两条路线是互斥的候选，不能同时采用，因此取最大值而不是相加。
- 第 3 题：✅ 正确。完整二维数组有 `(m + 1) * (n + 1)` 个格子，其中第 0 行和第 0 列是初始边界，真正由转移计算的是 `m * n` 个状态。每格做固定次数的比较、读取和写入，所以时间和空间都是 `O(mn)`。

### 正确答案

**第 1 题：** `first = "abc"`、`second = "ac"` 的表格。

> ```text
>       ""  a  ac
> ""     0  0   0
> a       0  1   1
> ab      0  1   1
> abc     0  1   2
> ```
> `common[3][2]` 比较 `first[2] = c` 与 `second[1] = c`，字符相同，所以读取左上 `common[2][1] = 1`，加上这个共同字符后得到 2。

**第 2 题：** 为什么不同字符不能相加？

> `common[i - 1][j]` 与 `common[i][j - 1]` 分别代表两种“舍弃一个末尾字符”的路线。一次具体的公共子序列只能选择其中一种对齐方式；把两者相加会把两个不同候选中的字符重复计入，得到一个实际上不存在的序列长度。

**第 3 题：** 二维表和复杂度。

> `common` 创建 `(m + 1)(n + 1)` 个位置；第 0 行和第 0 列是空前缀的边界，双层循环真正填 `m * n` 个状态。每个状态只做固定次数操作，所以填表时间是 `O(mn)`；创建表也为 `O(mn)`，先后相加仍为 `O(mn)`；完整表保存的数字数量为 `O(mn)`。

## 为什么要做错题回炉？

你已经完成了四种 DP：

```text
LC70：数走法
LC198：求最大金额
LC300：求最长序列
LC1143：比较两个前缀的最长公共序列
```

现在最容易出现的问题不是不会某一道题，而是看到新题时不知道从哪里开始。下面把四道题都压缩成同一张“做题检查单”。

## 第一步：先写一句状态定义

不要一看到题就写 `dp[i]`。先把下标翻译成人话：

| 题目 | 状态定义 | 下标在限制什么 |
|---|---|---|
| LC70 | `ways[i]`：到第 i 阶的走法数 | 一个楼梯前缀 |
| LC198 | `best[i]`：前 i 间房最多能偷的钱 | 一个房屋前缀 |
| LC300 | `lengths[i]`：必须以第 i 个数结尾的最长递增子序列 | 一个数组位置，并固定结尾 |
| LC1143 | `common[i][j]`：两个字符串前 i、前 j 个字符的最长公共子序列 | 两个字符串前缀 |

状态定义合格的标准是：

> 看到 `dp` 的下标，就能说出它对应的具体范围、结尾或限制；不能只说“表示最优答案”。

## 第二步：问“当前答案最后发生了什么”

这是推转移最稳定的问题。

### LC70：最后走 1 阶还是 2 阶？

```text
ways[i] = ways[i - 1] + ways[i - 2]
```

两条路线都是合法走法，而且每条走法必须属于其中一组，所以**计数问题的互斥分支相加**。

### LC198：最后一间房偷还是不偷？

```text
best[i] = max(best[i - 1], best[i - 2] + amounts[i - 1])
```

两条路线都是候选方案，但一次行动只能选其中一种，所以**最优值问题的互斥分支取最大**。

### LC300：当前数能接到哪个前驱后面？

```text
lengths[i] = max(lengths[j] + 1)
其中 j < i 且 numbers[j] < numbers[i]
```

这里不是只看“最后一步两种情况”，而是要枚举所有可能前驱，选择能接上的最长那条。

### LC1143：两个新字符相同还是不同？

```text
相同：common[i][j] = common[i - 1][j - 1] + 1
不同：common[i][j] = max(common[i - 1][j], common[i][j - 1])
```

状态的最后一部分不同，决定了要看左上，还是看上方与左方。

## 第三步：边界不是“写几个 0”，而是最小问题的答案

每个初始值都应该能用题意解释：

```text
LC70：ways[0] = 1，站在起点、什么也不走是一种完整方案。
LC198：best[0] = 0，没有房子就没有钱；best[1] = 第一间房金额。
LC300：每个 lengths[i] = 1，单独一个数就是长度 1 的递增子序列。
LC1143：common[0][j] = common[i][0] = 0，任意一边为空就没有公共字符。
```

如果初始值只是“看别人这么写”，遇到边界输入就很容易出错。

## 第四步：遍历顺序由依赖方向决定

逐题看当前状态依赖哪里：

| 题目 | 当前状态依赖 | 所以怎么遍历 |
|---|---|---|
| LC70 | `i - 1`、`i - 2` | i 从小到大 |
| LC198 | `i - 1`、`i - 2` | i 从小到大 |
| LC300 | 所有 `j < i` | i 从小到大，j 检查左侧 |
| LC1143 | 左上、上方、左方 | 行列都从小到大 |

不要问“DP 是不是都从左到右”。正确问题是：

> 当前格要读取哪些旧格？这些旧格必须在当前格之前被填好。

## 第五步：复杂度固定按三层数

以后看到代码，按下面顺序写草稿：

```text
1. 输入规模是什么？是 n，还是 m 和 n？
2. 循环/递归总共会处理多少个状态？
3. 每个状态内部做多少次与输入规模无关的工作？
```

### 一维单循环：LC70、LC198

```text
状态数约 n
每个状态 O(1)
总时间 n * O(1) = O(n)
```

如果还创建一个长度为 n 的状态数组：

```text
空间 O(n)
```

### 一维双循环：LC300

```text
第 0 个位置检查 0 个前驱
第 1 个位置检查 1 个前驱
...
第 n-1 个位置检查 n-1 个前驱
```

总次数：

```text
0 + 1 + ... + (n - 1)
= n(n - 1) / 2
= O(n^2)
```

### 二维双循环：LC1143

```text
m 行 * n 列 = mn 个状态
每个状态 O(1)
总时间 = O(mn)
```

完整二维表保存 mn 个数字：空间 `O(mn)`。

## 第六步：先区分“辅助空间”和“输出空间”

你需要在答案中明确口径：

```text
辅助空间：算法为了计算额外申请的内存，不算返回值本身。
总空间：辅助空间 + 题目要求返回的结果。
```

例如 LC78 必须返回 `2^n` 个子集，所以总输出空间是 `O(n * 2^n)`；但递归栈和 `path` 只有 `O(n)`。LC1143 不返回具体序列，只返回长度，二维 `common` 表才是主要辅助空间 `O(mn)`。
