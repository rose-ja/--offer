## LC739：每一天都在等“右边第一个更热的日子”

LC739「每日温度」：给你一个数组 `temperatures`，第 `i` 个位置表示第 `i` 天的气温。你要返回一个同长度数组：对于每一天，后面还要等几天才能遇到**第一个比今天更高**的温度；如果后面没有更高温度，填 0。

```text
temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
答案         = [ 1,  1,  4,  2,  1,  1,  0,  0]
```

例如：

```text
第 3 天是 71。
第 4 天是 69，不够高。
第 5 天是 72，第一个比 71 高。
所以第 3 天要等 5 - 3 = 2 天。
```

这类题有一个非常明显的问法：

> 对当前位置，右边第一个比它大的元素在哪里？

看到“右边第一个更大 / 更高 / 更晚满足条件”，就要想到单调栈。

## 先承认暴力解法，但看清它慢在哪里

最直接的方式是：对每一天，都向右一个个看，直到遇到更高温度。

```text
第 0 天向右找。
第 1 天再向右找。
第 2 天再向右找。
```

遇到一个很长的递减数组：

```text
[100, 99, 98, 97, ...]
```

第 0 天要看很多次，第 1 天也要看很多次。最坏情况下时间复杂度为 `O(n^2)`。

我们想让每一天只被处理有限次。

## 栈里到底存什么？先存“还没等到答案的下标”

单调栈不是一种新的数据结构，它只是一个普通数组，只不过我们规定它里面的元素要保持某种顺序。

本题的栈里存**下标**，不是温度值：

```text
stack = [0, 2, 5]
```

为什么存下标？因为找到更高温度后，答案要算等待天数：

```text
等待天数 = 当前下标 - 以前的下标
```

栈里的下标表示：这些天还没有等到右边第一个更高温度，所以它们都在“排队等待答案”。

## 为什么叫“单调递减栈”？

我们从左到右处理温度。栈从底到顶对应的温度保持**递减或相等**：

```text
栈底                            栈顶
温度：75, 72, 69
下标： 2,  5,  6
```

当今天的温度比栈顶那一天更高时，栈顶那天终于等到了第一个更高温度，可以出栈并填写答案。

为什么它一定是“第一个”？因为我们按天数从左到右走。当前天是它遇到的第一个能让它出栈的更高温度；中间经过的天如果也更高，它早就在当时出栈了。

## 核心规则：当前温度负责给过去的人发答案

遍历到今天 `currentIndex`、温度 `currentTemperature`：

1. 只要当前温度 `>` 栈顶那天的温度，栈顶那天就等到了答案：出栈，填写等待天数。
2. 可能不止一个过去的温度都比今天低，所以必须用 `while` 连续处理。
3. 处理完后，今天自己还没有未来的答案，把今天的下标压入栈中。

一句话：

> 栈里放等待者；今天比谁高，就给谁答案；最后今天也入栈等待未来。

## 手工走一遍短例子

`temperatures = [73, 74, 75, 71, 69, 72]`。

| 当前下标 | 当前温度 | 栈中等待者（按温度） | 本轮出栈和答案 | 本轮结束后的栈 |
|---:|---:|---|---|---|
| 0 | 73 | 空 | 无 | `[73]` |
| 1 | 74 | `[73]` | 74 > 73，弹出下标 0，答案 `1 - 0 = 1` | `[74]` |
| 2 | 75 | `[74]` | 75 > 74，弹出下标 1，答案 `2 - 1 = 1` | `[75]` |
| 3 | 71 | `[75]` | 71 不大于 75 | `[75, 71]` |
| 4 | 69 | `[75, 71]` | 69 不大于 71 | `[75, 71, 69]` |
| 5 | 72 | `[75, 71, 69]` | 72 > 69，填下标 4 为 1；72 > 71，填下标 3 为 2；72 不大于 75，停止 | `[75, 72]` |

第 5 天温度 72 一次给两天发了答案，所以这里必须是 `while`，不是 `if`。

## 可直接运行的代码

```js
/**
 * 返回每一天到右边第一个更高温度所需等待的天数。
 *
 * @param {number[]} temperatures
 * @returns {number[]}
 */
function dailyTemperatures(temperatures) {
  if (!Array.isArray(temperatures)) {
    return [];
  }
  if (temperatures.some((temperature) => !Number.isFinite(temperature))) {
    return [];
  }

  const waitDays = new Array(temperatures.length).fill(0);
  const pendingIndices = [];

  for (let currentIndex = 0; currentIndex < temperatures.length; currentIndex += 1) {
    const currentTemperature = temperatures[currentIndex];

    // 当前更高温度会解决所有比它低、且仍在等待的最近日期。
    while (
      pendingIndices.length > 0
      && currentTemperature > temperatures[pendingIndices[pendingIndices.length - 1]]
    ) {
      const previousIndex = pendingIndices.pop();
      waitDays[previousIndex] = currentIndex - previousIndex;
    }

    pendingIndices.push(currentIndex);
  }

  return waitDays;
}

console.log(dailyTemperatures([73, 74, 75, 71, 69, 72, 76, 73]));
// [1, 1, 4, 2, 1, 1, 0, 0]

console.log(dailyTemperatures([30, 40, 50, 60])); // [1, 1, 1, 0]
console.log(dailyTemperatures([30, 60, 90])); // [1, 1, 0]
console.log(dailyTemperatures([90, 80, 70])); // [0, 0, 0]
```

## 为什么相等温度不能出栈？

题目要求的是**更高**，不是“更高或相等”。所以 `currentTemperature > stackTopTemperature` 必须是严格大于。

例如：

```text
temperatures = [70, 70, 71]
```

读到第二个 70 时，第一个 70 不应该出栈，因为 70 不是比 70 更高的温度。读到 71 时，两个 70 都能出栈：

```text
答案 = [2, 1, 0]
```

若条件误写为 `>=`，第一个 70 会在第二天被错误地认为等到了更高温度。

## 为什么总复杂度还是 O(n)？

虽然代码里有 `for` 和 `while`，但每个下标：

```text
最多进栈一次，最多出栈一次。
```

因此所有 `push` 加所有 `pop` 的次数最多是 `2n`，总时间复杂度为 `O(n)`。栈在最坏情况（完全递减）会存下所有下标，空间复杂度为 `O(n)`。
