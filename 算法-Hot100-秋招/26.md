### 正确答案

**第 1 题：** 为什么 LC300 不能直接使用前一个状态的长度？

> 对 `numbers = [3, 100, 4]`，前两个数的最长递增子序列可以是 `[3, 100]`，长度为 2，但它的最后一个数 `100` 不小于 `4`，不能接上 `4`。所以状态必须固定结尾：`lengths[i]` 表示“必须以 `numbers[i]` 作为最后一个数字的最长递增子序列长度”。计算当前数时，先检查 `numbers[j] < numbers[i]`，再使用 `lengths[j] + 1`。

**第 2 题：** 一维 DP 的复杂度。

> 有 `n` 个主要状态，每个状态读取前两个状态并做一次 `max`，单次工作是 `O(1)`，因此转移部分是 `n * O(1) = O(n)`。初始化和循环是先后执行的，加法仍保留最高阶 `O(n)`。长度为 `n + 1` 的状态数组保存 `O(n)` 个值。

**第 3 题：** 二维 DP 的复杂度。

> 完整表格有 `(m + 1)(n + 1)` 个位置，第 0 行和第 0 列是边界，双层循环计算 `m * n` 个状态。每个状态只比较一次字符并读取固定数量的邻居，所以转移是 `O(mn)`；表格本身需要 `O(mn)` 空间。

## 一、先读懂题目：什么叫“区间重叠”？

LC56 给出若干区间，例如：

```text
[[1, 3], [2, 6], [8, 10], [9, 12]]
```

每个区间 `[start, end]` 表示从 `start` 到 `end` 的一段范围。题目要求把有重叠的区间合并，结果是：

```text
[[1, 6], [8, 12]]
```

为什么前两个能合并？因为 `[1, 3]` 和 `[2, 6]` 有共同部分 `2` 到 `3`。

为什么后两个能合并？因为 `[8, 10]` 和 `[9, 12]` 有共同部分 `9` 到 `10`。

先把“区间”想成一条数轴上的涂色范围：

```text
[1, 3]  : 1 2 3
[2, 6]  :   2 3 4 5 6
合并后   : 1 2 3 4 5 6  => [1, 6]
```

## 二、为什么要先排序？

如果输入已经按左端点排序：

```text
[[1, 3], [2, 6], [8, 10], [9, 12]]
```

我们只需要从左到右维护一个“当前合并区间”即可：

```text
当前合并区间 [1, 3]
读到 [2, 6]：2 <= 3，有重叠，合并为 [1, 6]
读到 [8, 10]：8 > 6，不重叠，保存 [1, 6]，开启新区间 [8, 10]
读到 [9, 12]：9 <= 10，有重叠，合并为 [8, 12]
```

但题目不保证输入有序。例如：

```text
[[8, 10], [1, 3], [2, 6], [9, 12]]
```

如果直接按输入顺序处理，当前看到的 `[8, 10]` 可能还不是最左边的区间，我们无法稳定判断后续区间应该归到哪里。

把区间按左端点从小到大排序后：

```text
[[1, 3], [2, 6], [8, 10], [9, 12]]
```

就获得了一个重要保证：

> 后面区间的左端点不会比当前区间更靠左，因此判断重叠时只需要比较“后面区间的左端点”和“当前合并区间的右端点”。

排序不是为了让代码看起来整齐，而是为了制造这个可证明的处理顺序。

## 三、重叠的判断：比较两个端点

假设当前已经合并出 `[currentStart, currentEnd]`，新读到 `[nextStart, nextEnd]`。因为已经按左端点排序，所以一定有：

```text
nextStart >= currentStart
```

此时只需要判断：

```text
nextStart <= currentEnd
```

### 情况 1：`nextStart <= currentEnd`

新区间从当前区间结束之前开始，说明至少有一个位置重叠：

```text
当前 [1, 3]，新 [2, 6]
2 <= 3，重叠
```

合并后的左端点仍然是 `currentStart`，右端点取两个右端点中较大的那个：

```text
[1, 3] + [2, 6] => [1, max(3, 6)] => [1, 6]
```

为什么不能无条件把右端点改成 `nextEnd`？因为新区间可能完全包含在当前区间中：

```text
[1, 10] + [2, 6] => [1, 10]
```

如果直接写成 `[1, 6]`，反而把原来覆盖的范围缩短了。

### 情况 2：`nextStart > currentEnd`

新区间从当前区间结束之后才开始，中间有空隙：

```text
当前 [1, 6]，新 [8, 10]
8 > 6，不重叠
```

当前区间已经确定，应该放入结果；新建一个当前区间，继续向后扫描。

注意边界：

```text
[1, 3] 和 [3, 5]
```

题目把端点相接也视为可以合并，所以 `3 <= 3` 时要合并为 `[1, 5]`。如果错误地写成 `<`，这个边界样例就会被拆开。

## 四、先不用代码，手工走完整个过程

输入：

```text
[[1, 3], [2, 6], [8, 10], [9, 12], [13, 15]]
```

排序后顺序不变。维护两个东西：

- `merged`：已经确定的结果。
- `current`：正在尝试扩大的区间。

| 新区间 | 当前区间 | 判断 | 动作 |
|---|---|---|---|
| `[2, 6]` | `[1, 3]` | `2 <= 3` | 当前变为 `[1, 6]` |
| `[8, 10]` | `[1, 6]` | `8 > 6` | 保存 `[1, 6]`，当前换成 `[8, 10]` |
| `[9, 12]` | `[8, 10]` | `9 <= 10` | 当前变为 `[8, 12]` |
| `[13, 15]` | `[8, 12]` | `13 > 12` | 保存 `[8, 12]`，当前换成 `[13, 15]` |

循环结束后，最后一个当前区间还没有遇到“下一个不重叠区间”来触发保存，所以必须补一次：

```text
merged = [[1, 6], [8, 12], [13, 15]]
```

这是本题常见错误：只在“不重叠”时保存，却忘记把最后的当前区间加入结果。

## 五、把自然语言变成算法步骤

现在可以把整题压缩成 5 步：

1. 检查输入是否为区间数组；空数组直接返回空数组。
2. 按每个区间的左端点升序排序。
3. 把第一个区间作为 `current`。
4. 从第二个区间开始扫描：重叠就扩大 `current`，不重叠就保存 `current` 并切换到新区间。
5. 扫描结束后，把最后的 `current` 保存到结果。

这里的核心不在“记住 5 步”，而在于每一步都对应一个已经解释过的事实：排序保证顺序，端点比较判断重叠，取 `max` 防止范围缩短，最后补保存防止遗漏。

## 六、正确性为什么成立？

排序后，区间是按左端点从左到右处理的。设当前区间是 `[currentStart, currentEnd]`：

- 如果 `nextStart <= currentEnd`，新区间和当前区间相交或端点相接。由于新区间的左端点不更小，合并后的左端点只能是 `currentStart`；右端点必须覆盖两者，因此取 `max(currentEnd, nextEnd)`。
- 如果 `nextStart > currentEnd`，新区间和当前区间之间存在空隙。由于后续区间的左端点只会更大，它们不可能再回头和当前区间产生重叠，所以当前区间可以安全放入结果。

因此，每次保存的区间都是已经无法再与后续区间合并的完整结果；循环结束后补入最后的当前区间，就不会遗漏任何一段范围。

## 七、复杂度：按“排序 + 扫描”拆开算

设区间数量为 `n`。

### 1. 排序

比较排序需要大约 `O(n log n)` 时间。不同 JavaScript 引擎的内部排序实现细节不影响这里的数量级判断。

### 2. 扫描

排序后从第 2 个区间扫描到第 `n` 个区间，每个区间只读取一次，判断和更新都是常数工作：

```text
扫描时间 = n * O(1) = O(n)
```

### 3. 合并

总时间是先排序、后扫描：

```text
O(n log n) + O(n) = O(n log n)
```

不能把两个阶段相乘，因为扫描不是对每个排序比较都重复执行，而是排序完成后只执行一遍。

### 4. 空间

如果直接对输入排序，额外空间取决于 JavaScript 引擎排序实现；为了不修改调用方数据，下面代码先复制区间。结果最多保存 `n` 个区间，因此输出空间是 `O(n)`；复制后的工作数据也需要 `O(n)`。在面试中可以说明：

```text
辅助空间：O(n)（为了复制并排序输入）
结果空间：O(n)
```

## 八、完整 JavaScript 实现

先看代码和前面的步骤如何一一对应：

```javascript
function merge(intervals) {
  if (!Array.isArray(intervals)) {
    throw new TypeError('intervals 必须是数组');
  }

  const sortedIntervals = intervals.map((interval, index) => {
    if (
      !Array.isArray(interval) ||
      interval.length < 2 ||
      !Number.isFinite(interval[0]) ||
      !Number.isFinite(interval[1])
    ) {
      throw new TypeError(`第 ${index} 个区间必须包含两个有限数字`);
    }

    const [start, end] = interval;
    if (start > end) {
      throw new RangeError(`第 ${index} 个区间的左端点不能大于右端点`);
    }

    // 复制每个区间，避免排序或合并时修改调用方传入的数据。
    return [start, end];
  });

  if (sortedIntervals.length === 0) {
    return [];
  }

  sortedIntervals.sort((first, second) => first[0] - second[0]);

  const merged = [sortedIntervals[0].slice()];

  for (let index = 1; index < sortedIntervals.length; index += 1) {
    const [nextStart, nextEnd] = sortedIntervals[index];
    const current = merged[merged.length - 1];

    if (nextStart <= current[1]) {
      current[1] = Math.max(current[1], nextEnd);
    } else {
      merged.push([nextStart, nextEnd]);
    }
  }

  return merged;
}
```

几个实现细节要特别看懂：

- `merged` 的最后一个区间就是当前正在合并的区间，因此不需要单独再维护一个 `current` 变量。
- `current[1]` 只在重叠时扩大，不能减小。
- 使用 `slice()` 和新数组，避免修改原始输入。
- `nextStart <= current[1]` 包含端点相接的情况。
