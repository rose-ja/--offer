## LC102：题目真正要求的不是“遍历”，而是“分层输出”

LC102「二叉树的层序遍历」要求从上到下、从左到右，按层返回节点值。

```text
        3
       / \
      9  20
        /  \
       15   7

答案：[[3], [9, 20], [15, 7]]
```

先看答案的形状：外层数组是一层一层的结果，内层数组是一层中的节点值。

```text
第 0 层：3
第 1 层：9、20
第 2 层：15、7
```

所以关键不只是“访问所有节点”，而是：

> 我必须清楚地区分：哪些节点属于当前层，哪些节点已经是下一层。

## 从根节点出发：当前层会生出下一层

一开始只有根节点，它就是当前层：

```text
currentLevel = [3]
nextLevel = []
```

遍历当前层的节点 3：把 3 的值收集到本层答案；再把它的孩子 9、20 放进下一层。

```text
本层答案 values = [3]
nextLevel = [9, 20]
```

此时才算第一层处理完。接下来把下一层接手为当前层：

```text
currentLevel = [9, 20]
```

然后重复同一件事。9 和 20 都处理完之前，绝不开始输出 15、7；因为 15、7 属于下一层。

这就是**广度优先搜索（BFS）**最朴素的样子：先把离根最近的一层全部处理完，再走到更远的一层。

## 手工追踪：两个数组如何保持“层”的边界

仍然使用上面的树。

| 当前轮 | `currentLevel` | 逐个处理后 `values` | 逐个收集后 `nextLevel` | 加入结果 |
|---|---|---|---|---|
| 1 | `[3]` | `[3]` | `[9, 20]` | `[[3]]` |
| 2 | `[9, 20]` | `[9, 20]` | `[15, 7]` | `[[3], [9, 20]]` |
| 3 | `[15, 7]` | `[15, 7]` | `[]` | `[[3], [9, 20], [15, 7]]` |

你只需要守住一个不变量：

> `currentLevel` 里永远只放同一层的节点；遍历它时发现的孩子，只能放进 `nextLevel`。

这就是题目能按层返回的原因，不是某个需要硬背的模板。

## 为什么不直接把孩子塞回当前层？

假设处理 3 时，立刻把 9、20 加回正在遍历的数组。这样“当前层数组”里就混入了下一层节点：

```text
原本当前层：[3]
处理 3 后混入：[3, 9, 20]
```

你失去了“第一层到哪里结束”的边界，也就不知道何时该把 `[3]` 放进结果。用 `nextLevel` 暂存孩子，相当于给两层之间画了一条明确的线。

## 可直接运行的代码

LeetCode 会提供 `TreeNode`。为了在本地直接运行，下面先补上这个最小节点定义。

```js
class TreeNode {
  constructor(value, left = null, right = null) {
    this.val = value;
    this.left = left;
    this.right = right;
  }
}

/**
 * 按从上到下、从左到右的顺序，返回二叉树每一层的节点值。
 *
 * @param {TreeNode | null} root
 * @returns {number[][]}
 */
function levelOrder(root) {
  if (root === null || root === undefined) {
    return [];
  }

  const levels = [];
  let currentLevel = [root];

  while (currentLevel.length > 0) {
    const values = [];
    const nextLevel = [];

    // 只遍历本层节点；孩子统一留给下一轮，层级就不会混在一起。
    for (const node of currentLevel) {
      values.push(node.val);

      if (node.left !== null && node.left !== undefined) {
        nextLevel.push(node.left);
      }
      if (node.right !== null && node.right !== undefined) {
        nextLevel.push(node.right);
      }
    }

    levels.push(values);
    currentLevel = nextLevel;
  }

  return levels;
}

const root = new TreeNode(
  3,
  new TreeNode(9),
  new TreeNode(20, new TreeNode(15), new TreeNode(7)),
);

console.log(levelOrder(root)); // [[3], [9, 20], [15, 7]]
console.log(levelOrder(null)); // []
console.log(levelOrder(new TreeNode(1))); // [[1]]
```

## 它和“队列”是什么关系？

你之后会看到另一种写法：用一个队列保存待处理节点，每次取出队首。它们本质相同：都是先处理先进入的数据。

本文的两个数组只是把队列按层分批：

```text
currentLevel：这一批现在就要处理的节点
nextLevel：这一批处理过程中，新发现、留给下一批的节点
```

对于 LC102，这种写法更直接，因为题目本身就要求“每一批”形成一个数组。等学到最短路径题时，再把它推广为“队列 + 层数 + visited”。

## 复杂度和边界

- 时间复杂度：`O(n)`。每个节点只进入一层、处理一次。
- 空间复杂度：`O(n)`。最宽的一层可能有接近 `n / 2` 个节点，需要暂存。
- 空树：没有任何层，返回 `[]`。
- 只有根节点：只有一层，返回 `[[root.val]]`。
- 某个节点只有一个孩子：只把实际存在的孩子放入下一层，不需要补 `null`。

## 面试时怎么说

可以用下面这段表达，不要只说“我用 BFS”：

> 我按层维护两组节点。`currentLevel` 保存当前要输出的一层，遍历时把节点值收集到 `values`，把它们的非空孩子收集到 `nextLevel`。当前层全部处理完后，把 `values` 加入答案，并用 `nextLevel` 替换当前层。这样每个节点只访问一次，时间复杂度是 `O(n)`。
