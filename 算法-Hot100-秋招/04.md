## 今天的变化：`Map` 不再统计次数，而是记住位置

LC1「两数之和」：给定整数数组 `numbers` 和目标值 `target`，找到两个不同下标，使这两个位置的数字相加等于 `target`，返回这两个下标。

```text
numbers = [2, 7, 11, 15]
target = 9
答案 = [0, 1]
原因：numbers[0] + numbers[1] = 2 + 7 = 9
```

这道题是 Easy，但它是哈希表最重要的第一题。因为它告诉你：`Map` 不只可以做“字符出现几次”的计数表，也可以做“某个值在哪里”的查找表。

## 先写出最直接的办法

我们可以选第一个数，再向后依次试第二个数：

```text
2 + 7？
2 + 11？
2 + 15？
7 + 11？
...
```

这当然能做出来，但数组有 `n` 个数时，第一层大约试 `n` 次，第二层又大约试 `n` 次，时间复杂度是 `O(n^2)`。

问题是：当你看到当前数字是 7、目标是 9 时，真正想问的不是“之前所有数字分别是多少”，而是：

> 之前有没有出现过 2？

如果能在很短时间内回答这个问题，就不需要双重循环。

## 把问题改写成“找搭档”

当前数字记为 `currentNumber`。它要凑出 `target`，还差的数字是：

```text
neededNumber = target - currentNumber
```

例如：

```text
target = 9
当前数字是 7
还差：9 - 7 = 2
```

于是每一步都做同一件事：

1. 算出当前数字需要的搭档 `neededNumber`。
2. 去 `Map` 问：之前出现过这个搭档吗？
3. 出现过就直接返回两个下标；没出现就把当前数字和它的下标存入 `Map`。

## 为什么一定是“先查，再存”？

数组里的两个下标必须不同。假设：

```text
numbers = [3, 3]
target = 6
```

读第一个 3 时，它需要另一个 3，但之前没有任何数字，因此把 `3 -> 0` 存入 `Map`。

读第二个 3 时，`Map` 里已经有 `3 -> 0`，于是返回 `[0, 1]`。

如果你先把当前 3 存进去，再查找 3，就可能拿到当前下标自己，错误返回 `[0, 0]` 或 `[1, 1]`。

所以顺序固定为：

> 先查搭档 -> 找到就返回 -> 找不到才存当前数字。

## 手工走一遍

`numbers = [2, 7, 11, 15]`，`target = 9`。

| 当前下标 | 当前数字 | 还差的搭档 | `Map` 中是否有搭档 | 本轮操作 | `Map` 结果 |
|---:|---:|---:|---|---|---|
| 0 | 2 | 7 | 没有 | 存入 `2 -> 0` | `{2: 0}` |
| 1 | 7 | 2 | 有，在下标 0 | 返回 `[0, 1]` | 不再继续 |

再看一个没有立刻命中的例子：`numbers = [3, 2, 4]`，`target = 6`。

```text
下标 0，数字 3，需要 3：之前没有，存 3 -> 0。
下标 1，数字 2，需要 4：之前没有，存 2 -> 1。
下标 2，数字 4，需要 2：Map 中有 2 -> 1，返回 [1, 2]。
```

## 可直接运行的代码

```js
/**
 * 找到两个不同下标，使对应数字之和等于 target。
 * 找不到时返回空数组；LeetCode 题目通常保证一定存在答案。
 *
 * @param {number[]} numbers
 * @param {number} target
 * @returns {number[]}
 */
function twoSum(numbers, target) {
  if (!Array.isArray(numbers) || !Number.isFinite(target)) {
    return [];
  }

  const indexByNumber = new Map();

  for (let currentIndex = 0; currentIndex < numbers.length; currentIndex += 1) {
    const currentNumber = numbers[currentIndex];
    if (!Number.isFinite(currentNumber)) {
      return [];
    }

    const neededNumber = target - currentNumber;

    // 设计意图：先查历史元素，保证返回的两个下标不会是同一个位置。
    if (indexByNumber.has(neededNumber)) {
      return [indexByNumber.get(neededNumber), currentIndex];
    }

    // 当前数字作为未来数字的搭档，保存它的下标。
    indexByNumber.set(currentNumber, currentIndex);
  }

  return [];
}

console.log(twoSum([2, 7, 11, 15], 9)); // [0, 1]
console.log(twoSum([3, 2, 4], 6)); // [1, 2]
console.log(twoSum([3, 3], 6)); // [0, 1]
console.log(twoSum([1, 2, 3], 10)); // []
```

## `Map` 的键和值各在保存什么？

这道题最容易只记住代码，忘记数据含义。请固定用一句话描述：

```text
键：已经出现过的数字。
值：这个数字第一次或最近一次出现的下标。
```

对于 LC1，保存第一次还是最近一次通常都可以，因为一旦找到答案就直接返回。这里的代码会覆盖重复数字的旧下标，但不会影响 `[3, 3]`，因为第二个 3 在覆盖之前已经先找到了第一个 3。

## 为什么它是 `O(n)`？

`for` 从头到尾走一次，执行 `n` 轮。每轮在 `Map` 中查询或存入一次，在平均情况下这两件事都是 `O(1)`。

因此：

```text
时间复杂度：O(n)
空间复杂度：O(n)
```

不要把 `Map` 当成“用了就一定更好”。当题目需要所有组合、要求排序后的双指针过程，或空间限制很紧时，其他方法可能更合适。LC1 的关键不是 `Map` 本身，而是看见“我要找某个值是否以前出现过”时，能立刻想到用它。
