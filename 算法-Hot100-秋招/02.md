## 今天只增加一个变化

上一篇 LC3 的窗口长度是不固定的：能放就放，重复了才缩。

今天学习 LC438「找到字符串中所有字母异位词」。它要求：在字符串 `s` 中，找出所有和 `p` **字母种类及次数都相同**的连续片段，返回这些片段的起始下标。

例子：

```text
s = "cbaebabacd"
p = "abc"
答案 = [0, 6]
```

原因：

- 下标 0 的 `"cba"` 和 `"abc"` 都有 a、b、c 各 1 个。
- 下标 6 的 `"bac"` 也满足。
- `"bae"` 不满足，因为它没有 c，却有 e。

这里最重要的词是**长度相同**。`p` 长度是 3，那么我们只检查 `s` 中长度为 3 的片段：

```text
c b a e b a b a c d
└───┘        窗口长度始终是 3
```

这就是固定长度窗口。它和上一篇最大的区别是：

> 每次右端加入一个字符后，只要窗口长度超过 `p.length`，就立刻移走最左边的一个字符。

不是“重复了才缩”，而是“长度超了就缩”。

## 先不用代码，手工移动一次

`s = "cbaebabacd"`，`p = "abc"`，窗口长度固定为 3。

| 右端加入 | 加入后窗口 | 长度 | 要不要移走最左边 | 最终检查 |
|---:|---|---:|---|---|
| 0 | `c` | 1 | 不要 | 还没满 |
| 1 | `cb` | 2 | 不要 | 还没满 |
| 2 | `cba` | 3 | 不要 | 计数和 `abc` 相同，记录 0 |
| 3 | `cbae` | 4 | 移走 `c`，得到 `bae` | 计数不匹配 |
| 4 | `baeb` | 4 | 移走 `b`，得到 `aeb` | 计数不匹配 |
| 5 | `aeba` | 4 | 移走 `a`，得到 `eba` | 计数不匹配 |
| 6 | `ebab` | 4 | 移走 `e`，得到 `bab` | 计数不匹配 |
| 7 | `baba` | 4 | 移走 `b`，得到 `aba` | 计数不匹配 |
| 8 | `abac` | 4 | 移走 `a`，得到 `bac` | 计数和 `abc` 相同，记录 6 |

表格里的“加入后窗口”在长度超过 3 时只是帮助理解，真正参与判断的始终是移走后的最后 3 个字符。

## `p` 的计数和窗口的计数

和 LC3 一样，我们用两个 `Map`：

- `requiredCount`：`p` 需要什么。比如 `p = "abb"`，记录 `a -> 1`、`b -> 2`。
- `windowCount`：当前这 3 个字符有什么。右端加入就加 1，左端离开就减 1。

当两个 `Map` 完全相同时，当前窗口就是一个异位词。

这里有一个适合初学者的做法：写一个小函数 `sameCount`，逐个比较两个 `Map`。它不一定是最极致的优化，但逻辑非常直观，先把正确性练稳。

## 可直接运行的代码

```js
/**
 * 找出 s 中所有与 p 同字母、同次数的连续片段起始下标。
 *
 * @param {string} s
 * @param {string} p
 * @returns {number[]}
 */
function findAnagrams(s, p) {
  if (typeof s !== 'string' || typeof p !== 'string') {
    return [];
  }
  if (p.length === 0 || p.length > s.length) {
    return [];
  }

  const requiredCount = new Map();
  for (const character of p) {
    requiredCount.set(character, (requiredCount.get(character) ?? 0) + 1);
  }

  const windowCount = new Map();
  const answer = [];
  let left = 0;

  for (let right = 0; right < s.length; right += 1) {
    const enteredCharacter = s[right];
    windowCount.set(
      enteredCharacter,
      (windowCount.get(enteredCharacter) ?? 0) + 1,
    );

    // 固定长度窗口：超过 p.length 就只移走一个最左字符。
    if (right - left + 1 > p.length) {
      const leavingCharacter = s[left];
      const remainingCount = windowCount.get(leavingCharacter) - 1;
      if (remainingCount === 0) {
        windowCount.delete(leavingCharacter);
      } else {
        windowCount.set(leavingCharacter, remainingCount);
      }
      left += 1;
    }

    // 窗口未满时不能成为答案；满了以后再比较计数。
    if (right - left + 1 === p.length && sameCount(windowCount, requiredCount)) {
      answer.push(left);
    }
  }

  return answer;
}

/**
 * 判断两个字符计数表是否完全相同。
 *
 * @param {Map<string, number>} firstCount
 * @param {Map<string, number>} secondCount
 * @returns {boolean}
 */
function sameCount(firstCount, secondCount) {
  if (firstCount.size !== secondCount.size) {
    return false;
  }

  for (const [character, count] of firstCount) {
    if (secondCount.get(character) !== count) {
      return false;
    }
  }
  return true;
}

console.log(findAnagrams('cbaebabacd', 'abc')); // [0, 6]
console.log(findAnagrams('abab', 'ab')); // [0, 1, 2]
console.log(findAnagrams('aaaa', 'aa')); // [0, 1, 2]
console.log(findAnagrams('a', 'aa')); // []
```

## 逐段解释最容易错的地方

### 为什么是 `if`，不是 `while`？

LC3 中可能需要连续移走多个字符，因为它的目标是“恢复不重复”。

LC438 的窗口长度每次只增加 1。它从最多 `p.length` 变成 `p.length + 1`，所以移走一个字符就刚好恢复固定长度。这里使用 `if` 是因为每轮最多超出 1 个，不需要连续移走。

### 为什么先加入，再移走？

右端每前进一步，我们先把新字符纳入统计。这样窗口代表的就是“最近的一段字符”。如果长度超出，再把最老的左端字符移走。

也可以反过来写，但初学阶段更容易漏掉边界。固定顺序更稳：**右端进入 -> 长度超出则左端离开 -> 窗口满了才判断**。

### 为什么 `sameCount` 先比较 `size`？

`p = "abb"` 时，窗口 `"abc"` 的 `a`、`b` 数量看似有部分相同，但多了 `c`、少了一个 `b`。只要不同字符种类数量不同，可以立刻返回 `false`；数量相同后，再逐个比较每个字符的次数。

当前这个版本每次比较最多遍历字符种类数。对于面试和初学阶段，先保证思路清楚；等你能稳定写对，再把“比较两个 Map”优化为一个 `matchedKinds` 变量，整体就能达到严格的 `O(n)`。

## 复杂度先说清楚

如果字符种类数量记为 `k`：

- 移动窗口本身是 `O(n)`。
- 每个窗口调用 `sameCount`，最多比较 `k` 种字符。
- 因此当前代码复杂度是 `O(n * k)`；在小写英文字母题目中 `k <= 26`，可以视为 `O(n)`。
- `Map` 空间复杂度是 `O(k)`。

这也是一个重要的工程判断：不要为了追求“理论上少一个常数”而把状态变量写得自己都不懂。先写出正确、可解释的版本，再根据题目字符集和时间限制决定是否优化。
