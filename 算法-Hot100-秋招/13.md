### 正确答案

**第 1 题：**

```text
numbers = [6, 7, 0, 1, 2, 4, 5]，target = 4。
第 1 轮：left = 0，mid = 3，right = 6，mid 值为 1。
          右半 [1, 2, 4, 5] 有序，4 在 (1, 5] 内，left = 4。
第 2 轮：left = 4，mid = 5，right = 6，mid 值为 4，返回 5。
```

## LC34：普通二分找到一个，边界二分找到整段

LC34「在排序数组中查找元素的第一个和最后一个位置」：给定一个非递减数组 `numbers` 和目标值 `target`，返回 target 第一次和最后一次出现的下标；不存在返回 `[-1, -1]`。

```text
numbers = [5, 7, 7, 8, 8, 10]
target = 8
答案 = [3, 4]
```

普通二分只能保证“找到一个 8”，例如可能返回 3，也可能返回 4。但题目问的是一整段 8 的左右边界，因此：

> 即使 `numbers[mid] === target`，也不能立刻返回。我们还要继续向左或向右确认有没有同样的 target。

## 不要想着“找 target”，改为“找第一个满足条件的位置”

边界二分最稳定的理解不是去背两套代码，而是提出一个问题：

```text
第一个值 >= 某个阈值的位置在哪里？
```

这叫 `lowerBound`。例如：

```text
numbers = [1, 2, 2, 2, 5]

第一个 >= 2 的位置是 1。
第一个 >= 3 的位置是 4。
第一个 >= 6 的位置不存在，返回 numbers.length，也就是 5。
```

为什么它能用于 LC34？

```text
第一个 target 的位置 = 第一个 >= target 的位置。
最后一个 target 的位置 = 第一个 > target 的位置 - 1。
```

所以我们需要两个边界：

```text
lowerBound(target)：第一个 >= target。
upperBound(target)：第一个 > target。
```

## `lowerBound`：命中时仍然向左找

目标是第一个 `>= threshold` 的下标。

当 `numbers[mid] >= threshold` 时，mid 可能就是答案，但左边也可能有更早的符合位置。因此：

```text
先记录 mid 为候选。
right = mid - 1，继续去左边找。
```

当 `numbers[mid] < threshold` 时，mid 及其左边都不可能满足条件：

```text
left = mid + 1。
```

这就是“第一个 >=”的全部逻辑。

## `upperBound`：命中时仍然向右找

目标是第一个 `> threshold` 的下标。

当 `numbers[mid] > threshold` 时，mid 可能是第一个更大的数，继续向左缩小：

```text
right = mid - 1。
```

当 `numbers[mid] <= threshold` 时，mid 和左边都还不够大，向右走：

```text
left = mid + 1。
```

最后得到“第一个 > target”后，向左退一格，就是最后一个 target。

## 手工走一次：找 8 的第一个位置

```text
numbers = [5, 7, 7, 8, 8, 10]
target = 8
```

找第一个 `>= 8`：

| 轮次 | `left` | `mid` | `right` | `numbers[mid]` | 判断 | 下一步 |
|---:|---:|---:|---:|---:|---|---|
| 1 | 0 | 2 | 5 | 7 | 7 < 8，不可能满足 | `left = 3` |
| 2 | 3 | 4 | 5 | 8 | 8 >= 8，可能是答案，但继续向左 | `right = 3` |
| 3 | 3 | 3 | 3 | 8 | 8 >= 8，继续向左 | `right = 2` |

循环结束时 `left = 3`，这就是第一个 8 的下标。

再找第一个 `> 8`，会得到下标 5（值为 10），所以最后一个 8 是 `5 - 1 = 4`。

## 可直接运行的代码

```js
/**
 * 返回 target 在非递减数组中的第一个和最后一个下标。
 * target 不存在时返回 [-1, -1]。
 *
 * @param {number[]} numbers
 * @param {number} target
 * @returns {number[]}
 */
function searchRange(numbers, target) {
  if (!Array.isArray(numbers) || !Number.isFinite(target)) {
    return [-1, -1];
  }
  if (numbers.some((number) => !Number.isFinite(number))) {
    return [-1, -1];
  }

  const firstIndex = lowerBound(numbers, target);
  if (firstIndex === numbers.length || numbers[firstIndex] !== target) {
    return [-1, -1];
  }

  const lastIndex = upperBound(numbers, target) - 1;
  return [firstIndex, lastIndex];
}

/**
 * 返回第一个值 >= threshold 的下标；不存在时返回 numbers.length。
 *
 * @param {number[]} numbers
 * @param {number} threshold
 * @returns {number}
 */
function lowerBound(numbers, threshold) {
  let left = 0;
  let right = numbers.length - 1;
  let answer = numbers.length;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (numbers[mid] >= threshold) {
      answer = mid;
      right = mid - 1;
    } else {
      left = mid + 1;
    }
  }

  return answer;
}

/**
 * 返回第一个值 > threshold 的下标；不存在时返回 numbers.length。
 *
 * @param {number[]} numbers
 * @param {number} threshold
 * @returns {number}
 */
function upperBound(numbers, threshold) {
  let left = 0;
  let right = numbers.length - 1;
  let answer = numbers.length;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (numbers[mid] > threshold) {
      answer = mid;
      right = mid - 1;
    } else {
      left = mid + 1;
    }
  }

  return answer;
}

console.log(searchRange([5, 7, 7, 8, 8, 10], 8)); // [3, 4]
console.log(searchRange([5, 7, 7, 8, 8, 10], 6)); // [-1, -1]
console.log(searchRange([], 0)); // [-1, -1]
console.log(searchRange([2, 2, 2], 2)); // [0, 2]
console.log(searchRange([1], 1)); // [0, 0]
```

## 为什么候选答案初始值是 `numbers.length`？

如果数组中所有值都小于阈值，例如：

```text
numbers = [1, 2, 3]
threshold = 5
```

不存在任何位置满足 `numbers[index] >= 5`。在数组下标中，用 `numbers.length` 表示“所有元素之后的位置”非常合适：

```text
数组下标：0  1  2
插入位置：        3
```

这也是 `lowerBound` 的一个额外用途：它不仅能找已有元素的左边界，也能返回应该插入的位置。
