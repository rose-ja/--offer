## LC33：有序数组被从中间切开并接到前面

LC33「搜索旋转排序数组」：原数组升序且没有重复元素，例如：

```text
[0, 1, 2, 4, 5, 6, 7]
```

把前面一段挪到最后，或把后面一段挪到前面，会得到：

```text
[4, 5, 6, 7, 0, 1, 2]
```

给定这样的数组和 `target`，找到目标值的下标；不存在返回 `-1`。

```text
numbers = [4, 5, 6, 7, 0, 1, 2]
target = 0
答案 = 4
```

数组不再从左到右完全递增，所以不能直接使用“`numbers[mid] < target` 就右移 left”这一条普通二分规则。

但它没有完全失去规律：

> 每次取中点后，`[left, mid]` 和 `[mid, right]` 中，至少有一半仍然是正常递增的有序区间。

这就是继续二分的依据。

## 为什么至少一半有序？

旋转数组只有一个“断开点”：从较大的数突然回到较小的数，例如：

```text
7 -> 0
```

中点把当前区间分为左右两半。一个区间里只有一个断开点，因此它不可能同时落在左右两半中：至少有一半不含断开点，仍是从小到大排列。

例如：

```text
当前区间：[4, 5, 6, 7, 0, 1, 2]
left = 0，mid = 3，right = 6

左半：[4, 5, 6, 7]  是有序的。
右半：[7, 0, 1, 2]  含断开点，不是完整有序区间。
```

注意右半实际查询范围会从 `mid + 1` 开始，即 `[0, 1, 2]`；上面将 `mid` 同时展示，是为了说明中点把整体切开的方式。

## 每轮只做两个判断

先按普通二分一样检查中点：

```js
if (numbers[mid] === target) {
  return mid;
}
```

中点不是目标时，按下面顺序判断。

### 情况一：左半边有序

若：

```js
numbers[left] <= numbers[mid]
```

说明 `[left, mid]` 是递增的。

现在问：目标是否落在这个有序范围内？

```text
numbers[left] <= target < numbers[mid]
```

- 在这个范围内：保留左半边，`right = mid - 1`。
- 不在这个范围内：左半边可以排除，`left = mid + 1`。

为什么右侧是 `< numbers[mid]` 而不是 `<=`？因为一开始已经处理了 `numbers[mid] === target`。中点不是答案时，不需要再把它保留在区间中。

### 情况二：右半边有序

否则左半边不可能有序，因此 `[mid, right]` 有序。

目标是否落在右半边范围内：

```text
numbers[mid] < target <= numbers[right]
```

- 在范围内：保留右半边，`left = mid + 1`。
- 不在范围内：排除右半边，`right = mid - 1`。

## 手工走一遍：找 0

```text
numbers = [4, 5, 6, 7, 0, 1, 2]
target = 0
```

| 轮次 | `left` | `mid` | `right` | 三个值 | 哪边有序 | target 是否在有序范围 | 下一步 |
|---:|---:|---:|---:|---|---|---|---|
| 1 | 0 | 3 | 6 | 4, 7, 2 | 左边 `[4..7]` | 0 不在 `[4, 7)` | `left = 4` |
| 2 | 4 | 5 | 6 | 0, 1, 2 | 左边 `[0..1]` | 0 在 `[0, 1)` | `right = 4` |
| 3 | 4 | 4 | 4 | 0, 0, 0 | 中点就是 target | - | 返回 4 |

每轮都至少排除了近一半候选位置，因此复杂度仍是 `O(log n)`。

## 再走一次：找 6

同一个数组找 6：

```text
第 1 轮：mid 是 7，左边 [4, 5, 6, 7] 有序，6 在 [4, 7) 内，right 移到 2。
第 2 轮：当前区间 [4, 5, 6]，mid 是 5，左边 [4, 5] 有序，6 不在 [4, 5) 内，left 移到 2。
第 3 轮：mid 是 6，找到下标 2。
```

重点不是背“左有序 / 右有序”的代码，而是每次都问：**哪半边正常递增？target 是否在这半边的数值范围里？**

## 可直接运行的代码

```js
/**
 * 在无重复元素的旋转升序数组中查找 target。
 *
 * @param {number[]} numbers
 * @param {number} target
 * @returns {number}
 */
function searchRotatedArray(numbers, target) {
  if (!Array.isArray(numbers) || !Number.isFinite(target)) {
    return -1;
  }
  if (numbers.some((number) => !Number.isFinite(number))) {
    return -1;
  }

  let left = 0;
  let right = numbers.length - 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (numbers[mid] === target) {
      return mid;
    }

    if (numbers[left] <= numbers[mid]) {
      // 左半边有序。target 在这里时，保留左半边继续找。
      if (numbers[left] <= target && target < numbers[mid]) {
        right = mid - 1;
      } else {
        left = mid + 1;
      }
    } else {
      // 右半边有序。target 在这里时，保留右半边继续找。
      if (numbers[mid] < target && target <= numbers[right]) {
        left = mid + 1;
      } else {
        right = mid - 1;
      }
    }
  }

  return -1;
}

console.log(searchRotatedArray([4, 5, 6, 7, 0, 1, 2], 0)); // 4
console.log(searchRotatedArray([4, 5, 6, 7, 0, 1, 2], 3)); // -1
console.log(searchRotatedArray([1], 0)); // -1
console.log(searchRotatedArray([1], 1)); // 0
console.log(searchRotatedArray([5, 1, 3], 5)); // 0
```

## 最容易写错的三个地方

### 1. 先判断 `mid` 是否命中

范围判断中故意写了严格不等号。若不先处理 `numbers[mid] === target`，目标恰好在中点时可能被错误排除。

### 2. 左半边的范围是左闭右开

左半有序且 mid 未命中时，写：

```js
numbers[left] <= target && target < numbers[mid]
```

目标等于 `numbers[left]` 时应保留左半；目标等于 `numbers[mid]` 已在前面返回。

### 3. 本题没有重复值

当前判断依赖“左半有序”与“右半有序”能明确区分。若数组允许重复，例如两端和中点都相同，不能仅凭比较确定哪半边有序，需要额外处理。这是另一个题型，当前不展开。
