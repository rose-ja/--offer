- 第 3 题：✅ 正确。第 1 个位置有 `n` 种选法，之后依次为 `n - 1`、`n - 2`，直到 1 种，因此排列数是 `n * (n - 1) * ... * 1 = n!`。

### 正确答案

**第 1 题：** `path = [1, 3]`、`used = [true, false, true]` 时如何继续？

> 只有下标 1 的数字 2 可选。先选它得到 `[1, 3, 2]` 并复制进答案；返回到当前层后撤销本层刚选的 3，因此恢复为 `path = [1]`、`used = [true, false, false]`。注意：每一层只撤销自己刚刚做出的那一次选择。

**第 2 题：** 为什么必须复制 `path`？

> 数组是引用类型。`result.push(path)` 让答案数组中的多个位置都指向同一个可变数组；回溯调用 `pop()` 后，过去保存的“答案”也一起变了。`result.push([...path])` 创建快照，后续修改原 `path` 不会影响它。

**第 3 题：** 为什么排列数是 `n!`？

> 填第 1 个位置有 `n` 种可能；选走一个后，填第 2 个位置只剩 `n - 1` 种；持续相乘直到最后一位只有 1 种。因此总数是 `n!`。

## LC78：子集不是“排列少一点”，而是每个数做一次二选一

LC78「子集」：给定互不相同的整数数组，返回所有可能的子集。子集不要求元素顺序，空集也必须在答案中。

```text
numbers = [1, 2, 3]

一个可能的答案顺序：
[]
[3]
[2]
[2, 3]
[1]
[1, 3]
[1, 2]
[1, 2, 3]
```

先和 LC46 对比：

| 题目 | 当前一步在决定什么 | 同一个元素能否以后再选 |
|---|---|---|
| 全排列 | 下一个位置放哪个未使用数字 | 可以，在别的位置使用 |
| 子集 | 当前数字要不要放入集合 | 不可以，处理完就进入下一个数字 |

对子集来说，数字 1 只有两种状态：选，或不选；数字 2 也只有两种状态；每个数字只做一次决定。

> `backtrack(index)` 的职责：前面下标 `0` 到 `index - 1` 的数字都已决定选或不选；现在决定 `numbers[index]` 的去留。

## 用一棵二叉决策树看 `[1, 2, 3]`

每层处理一个数字。左边表示“不选”，右边表示“选”。

```text
处理 1
├── 不选 1，path = []
│   ├── 不选 2，path = []
│   │   ├── 不选 3 -> []
│   │   └── 选 3   -> [3]
│   └── 选 2，path = [2]
│       ├── 不选 3 -> [2]
│       └── 选 3   -> [2, 3]
└── 选 1，path = [1]
    └── 后续继续对 2、3 做同样的二选一
```

走到第 `index === numbers.length` 层，所有数字都已决定，当前 `path` 就是一份完整子集。

这里没有 `used` 数组，因为不存在“回到前面重新选同一个数字”。递归的 `index` 只会向前移动：0、1、2、3。

## 代码中的三步：不选、选、撤销

处理当前数字 `numbers[index]` 时：

```text
1. 不选它：直接处理下一个 index。
2. 选它：push 到 path，处理下一个 index。
3. 选的分支结束后：pop，恢复给上一层。
```

“不选”没有改动 `path`，所以不需要撤销；“选”改动了 `path`，所以必须配一个 `pop()`。

## 可直接运行的代码

LC78 规定输入数字互不相同。下面使用“每个数选或不选”的递归写法，递归树结构与复杂度最直观。

```js
/**
 * 返回互不相同数字的所有子集。
 *
 * @param {number[]} numbers
 * @returns {number[][]}
 */
function subsets(numbers) {
  if (!Array.isArray(numbers) || numbers.some((number) => !Number.isFinite(number))) {
    return [];
  }
  if (new Set(numbers).size !== numbers.length) {
    return [];
  }

  const result = [];
  const path = [];

  /**
   * 决定从 index 开始的每个数字是否加入当前 path。
   *
   * @param {number} index
   */
  function backtrack(index) {
    if (index === numbers.length) {
      // 保存快照；回溯时 path 会继续变化。
      result.push([...path]);
      return;
    }

    // 分支一：当前数字不加入子集。
    backtrack(index + 1);

    // 分支二：当前数字加入子集，处理完后恢复现场。
    path.push(numbers[index]);
    backtrack(index + 1);
    path.pop();
  }

  backtrack(0);
  return result;
}

console.log(subsets([1, 2, 3]));
// [[], [3], [2], [2, 3], [1], [1, 3], [1, 2], [1, 2, 3]]
console.log(subsets([0])); // [[], [0]]
console.log(subsets([])); // [[]]
console.log(subsets([1, 1])); // []：LC78 的输入不允许重复数字
```

## 从今天起，复杂度按这四步计算

以后看到复杂度，不要先背 `O(...)`。固定按下面四步问：

1. **输入规模是什么？** 本题是 `n = numbers.length`。
2. **主过程会产生多少条完整路径或执行多少轮？** 本题每个数字二选一，共 `2^n` 条完整决策路径。
3. **每条路径或每轮额外做多少工作？** 本题到叶子时，要复制长度最多为 `n` 的 `path`。
4. **总工作量如何合并？** “有多少次”乘以“每次成本”；如果是先后执行的独立代码段，才相加。

下面不跳步，拿 `n = 3` 的子集树实际数一次。

## 第一步：为什么是 `2^n` 个子集？

每个数字都有两种选择：选或不选。

```text
数字 1：2 种选择
数字 2：2 种选择
数字 3：2 种选择

总完整路径：2 * 2 * 2 = 2^3 = 8
```

一般有 `n` 个数字时，连续乘 `n` 个 2：

```text
2 * 2 * ... * 2 = 2^n
```

每条完整路径恰好对应一个子集。例如“选 1、不选 2、选 3”对应 `[1, 3]`。不同的选/不选记录会得到不同子集，所以共有 `2^n` 个子集。

## 第二步：递归调用次数为什么也是 `O(2^n)`？

决策树不只有叶子，还包含中间节点。`n = 3` 时每层节点数为：

| 已决定的数字个数 | 树的这一层有多少调用 | 原因 |
|---:|---:|---|
| 0 | `1` | 还没有决定，只有根调用 |
| 1 | `2` | 第一个数字选或不选 |
| 2 | `4` | 前两个数字各有两种组合 |
| 3 | `8` | 所有数字都决定完，8 个叶子 |

总调用数是：

```text
1 + 2 + 4 + 8 = 15
```

对一般的 `n`：

```text
1 + 2 + 4 + ... + 2^n = 2^(n + 1) - 1
```

大 O 忽略常数和低阶项，`2^(n + 1) - 1` 与 `2 * 2^n` 同阶，所以是 `O(2^n)`。这描述的是“遍历整棵决策树本身”的成本。

## 第三步：为什么最终时间是 `O(n * 2^n)`？

很多人停在上一步，写 `O(2^n)`；但本题要**返回每个子集的数组**，叶子处有：

```js
result.push([...path]);
```

`[...path]` 不是一个常数动作。它需要把 `path` 中的每个元素逐个复制到新数组：

```text
复制 []         需要 0 次元素复制
复制 [1]        需要 1 次元素复制
复制 [1, 3]     需要 2 次元素复制
复制 [1, 2, 3]  需要 3 次元素复制
```

每一个子集长度最多为 `n`。做一个上界估算：

```text
最多有 2^n 个子集
每次复制最多 n 个元素
总复制工作最多为 n * 2^n
```

再加上遍历递归树的 `O(2^n)`，总时间是：

```text
O(2^n) + O(n * 2^n) = O(n * 2^n)
```

为什么最后保留第二项？当 `n >= 1` 时，`n * 2^n` 至少与 `2^n` 一样大，所以它主导总成本。

更精确地说，所有子集的总元素个数是 `n * 2^(n - 1)`：每个固定数字恰好出现在一半子集里，即 `2^(n - 1)` 个。这仍然是 `O(n * 2^n)`。

> 结论不是“回溯永远是 `O(n * 2^n)`”。这里多出的 `n`，来自于题目要求复制并返回长度不一的所有数组。

## 第四步：空间复杂度要先问“算不算输出”

空间至少要说清两种口径：

| 口径 | 保存了什么 | 本题复杂度 |
|---|---|---|
| 辅助空间，不算 `result` | 递归调用栈最多 `n` 层，加上 `path` 最多 `n` 个元素 | `O(n)` |
| 总空间，算上返回结果 | 全部子集中的所有元素，加上辅助空间 | `O(n * 2^n)` |

不要把“递归树有 `2^n` 个节点”误认为调用栈会同时放 `2^n` 层。深度优先递归一次只沿一条路径向下走，最深只走过 `n` 个数字，因此栈深是 `O(n)`。

## 一个可迁移的复杂度判断表

| 代码或结构 | 先数什么 | 常见结果 |
|---|---|---|
| 单层 `for` 从 0 到 `n - 1` | 循环次数 `n` | `O(n)` |
| 两层嵌套，各执行 `n` 次 | 每轮内层都跑 `n` 次，乘法 | `O(n^2)` |
| 两段先后执行的循环 | 两段成本相加，保留大的 | `O(n) + O(n^2) = O(n^2)` |
| 每层固定二选一、深度 `n` | 叶子数 `2^n` | `O(2^n)`，再看叶子工作量 |
| 排列：第 1 层 `n` 选项，后续递减 | 叶子数 `n!` | `O(n!)`，再看每个答案复制成本 |

LC46 的 `O(n * n!)` 就能用同一套流程复算：有 `n!` 个完整排列，每份排列长度为 `n`，保存快照需要 `O(n)`，所以总时间是 `O(n * n!)`。

## 面试时怎么说

> 我把每个数字是否加入子集看作一次二选一决策，因此深度为 n 的决策树有 `2^n` 个叶子，也就是 `2^n` 个子集。遍历递归树是 `O(2^n)`；但每个叶子要复制当前路径，单次最多 `O(n)`，所以返回全部子集的时间复杂度是 `O(n * 2^n)`。不算输出时，递归栈和 path 最多都是 n，辅助空间为 `O(n)`；算上返回结果则是 `O(n * 2^n)`。
