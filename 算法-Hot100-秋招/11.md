## LC141：链表为什么会“走不出去”？

LC141「环形链表」：给你一个链表头节点 `head`。若某个节点的 `next` 指回链表前面某个节点，链表就形成环；判断链表是否有环。

```text
无环：1 -> 2 -> 3 -> null

有环：1 -> 2 -> 3 -> 4
              ^         |
              |_________|
```

无环链表一直沿着 `next` 走，最终一定会遇到 `null`。有环链表则永远会在环中绕圈，永远遇不到 `null`。

最直接的做法是用 `Set` 保存访问过的节点：再次看见同一个节点就是有环。这是正确的，但需要 `O(n)` 额外空间。

这一题更重要的解法是快慢指针，只用 `O(1)` 额外空间。

## 两个指针分别怎么走？

```text
slow：每轮走 1 步。
fast：每轮走 2 步。
```

两者都从头节点出发：

```js
let slow = head;
let fast = head;
```

每一轮：

```js
slow = slow.next;
fast = fast.next.next;
```

这里比较的是节点对象本身：

```js
slow === fast
```

不是比较 `slow.val === fast.val`。不同节点可以存相同值，例如 `1 -> 1 -> null`，它没有环，但两个值都可能是 1。

## 无环时：fast 会先走到尽头

对无环链表：

```text
1 -> 2 -> 3 -> null
```

fast 每轮要走两步，所以走之前必须确认：

```js
fast !== null && fast.next !== null
```

否则 `fast.next.next` 会访问到空对象的 `next`，运行时报错。

只要 `fast` 或 `fast.next` 为 `null`，说明 fast 已经到链表尽头，链表无环，返回 `false`。

## 有环时：为什么快指针一定会追上慢指针？

先不用复杂公式，把环想成跑道。

slow 和 fast 先后进入环后：

```text
slow 每轮走 1 格。
fast 每轮走 2 格。
```

因此 fast 每轮都会比 slow 多走 1 格。环的长度是有限的，fast 与 slow 之间的距离会每轮缩短 1 格；距离缩到 0 时，它们就在同一个节点相遇。

关键前提是：两个指针一旦进了环就再也出不去。fast 持续追赶，有限长度的跑道上一定会追上。

> 慢指针负责保证不会跳过节点；快指针负责制造相对速度。无环时快指针先到终点，有环时快指针必然在环里追上慢指针。

## 手工走一遍有环链表

链表：

```text
3 -> 2 -> 0 -> -4
     ^              |
     |______________|
```

节点 `-4.next` 指向值为 2 的节点。注意下表中的值只方便阅读，真正判断的是节点是否为同一个对象。

| 轮次 | slow 走 1 步后 | fast 走 2 步后 | 是否相同节点 |
|---:|---|---|---|
| 开始 | 3 | 3 | 是，但还没有移动，不能据此判断有环 |
| 1 | 2 | 0 | 否 |
| 2 | 0 | 2 | 否 |
| 3 | -4 | -4 | 是，返回 `true` |

为什么不能一开始就检查 `slow === fast`？因为它们一开始都指向 `head`，无环链表也会相等。必须至少移动一轮后再检查。

## 可直接运行的代码

下面包含本地构造有环链表的辅助函数。提交 LeetCode 时只保留 `hasCycle`，平台会提供 `ListNode`。

```js
function ListNode(value, next = null) {
  this.val = value;
  this.next = next;
}

/**
 * 判断单链表是否存在环。
 *
 * @param {ListNode | null} head
 * @returns {boolean}
 */
function hasCycle(head) {
  let slow = head;
  let fast = head;

  // fast 每轮要访问两次 next，条件先保证这两次访问都安全。
  while (fast !== null && fast.next !== null) {
    slow = slow.next;
    fast = fast.next.next;

    // 比较节点引用，而不是节点保存的数值。
    if (slow === fast) {
      return true;
    }
  }

  return false;
}

function arrayToList(values, cycleEntryIndex = -1) {
  if (!Array.isArray(values) || values.length === 0) {
    return null;
  }

  const nodes = values.map((value) => new ListNode(value));
  for (let index = 0; index < nodes.length - 1; index += 1) {
    nodes[index].next = nodes[index + 1];
  }

  if (Number.isInteger(cycleEntryIndex)
    && cycleEntryIndex >= 0
    && cycleEntryIndex < nodes.length) {
    nodes[nodes.length - 1].next = nodes[cycleEntryIndex];
  }

  return nodes[0];
}

console.log(hasCycle(arrayToList([3, 2, 0, -4], 1))); // true
console.log(hasCycle(arrayToList([1, 2], 0))); // true
console.log(hasCycle(arrayToList([1]))); // false
console.log(hasCycle(null)); // false
console.log(hasCycle(arrayToList([1, 1]))); // false，值相同不代表节点相同
```

## `while` 条件为什么必须同时检查两个部分？

这一行：

```js
while (fast !== null && fast.next !== null)
```

不是为了形式完整，而是与循环体精确配套：

```js
fast = fast.next.next;
```

若只写 `while (fast !== null)`，当 fast 恰好在最后一个节点时，`fast.next` 是 `null`，继续访问 `fast.next.next` 会抛错。

若只写 `while (fast.next !== null)`，初始 `head` 为 `null` 时，访问 `fast.next` 本身就会抛错。
