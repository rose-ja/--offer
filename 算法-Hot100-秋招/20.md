> 第 2 分钟：`nextLevel = [(0,2), (1,1)]`。

> 第 4 分钟：`nextLevel = [(2,2)]`。

> 当前层中可能有多个腐烂橘子都能触及同一个新鲜橘子。第一个来源把它从 1 改成 2 后，第二个来源检查时会发现它不再是新鲜橘子，从而跳过。这样该格子最多入队一次，`freshCount` 也只减一次。

**第 3 题：** 为什么两个 `O(mn)` 相加？

## LC207：课程依赖形成环，就永远没有第一门课可上

LC207「课程表」：共有 `courseCount` 门课，编号为 `0` 到 `courseCount - 1`。`prerequisites` 中每个 `[course, prerequisite]` 表示“要学 `course`，必须先学 `prerequisite`”。判断能否修完全部课程。

```text
courseCount = 2
prerequisites = [[1, 0]]

含义：0 -> 1
先学 0，再学 1，因此可以完成。
```

如果是：

```text
prerequisites = [[1, 0], [0, 1]]

0 -> 1 -> 0
```

0 等 1，1 又等 0，没有一门课可以作为起点，所以无法完成。

这就是一个有向图问题：

```text
课程：顶点（vertex，记作 V）
先修关系：有向边（edge，记作 E）
```

题目真正问的是：

> 能否找到一种顺序，让每门课的前置课程都排在它之前？

## 暂时不要看代码：先手工“解锁”课程

先只看下面四门课，不需要知道图、入度或拓扑排序是什么：

```text
courseCount = 4

[1, 0]：学 1 前必须完成 0
[2, 0]：学 2 前必须完成 0
[3, 1]：学 3 前必须完成 1
[3, 2]：学 3 前必须完成 2
```

把每门课现在还欠的条件写成清单：

| 课程 | 现在还欠什么？ | 此刻能否开始？ |
|---:|---|---|
| 0 | 什么都不欠 | 能 |
| 1 | 欠 0 | 不能 |
| 2 | 欠 0 | 不能 |
| 3 | 欠 1、2 | 不能 |

这里有一个很朴素的规则：

> 一门课的“还欠清单”为空时，它就可以开始学习。

因此第一步不能任选 1、2、3，只能选 0：

```text
已完成：0
```

完成 0 后，不是所有课程都完成了。你只需要找出“谁把 0 写在了自己的还欠清单里”：课程 1 和课程 2。

```text
课程 1：原来欠 0，完成 0 后不再欠任何课，可以开始。
课程 2：原来欠 0，完成 0 后不再欠任何课，可以开始。
课程 3：仍然欠 1、2，不能开始。
```

于是现在可开始的课程有 1 和 2。先后顺序可以不同，但都不会影响能否完成：

```text
已完成：0
现在可开始：1、2
```

假设先完成 1：课程 3 的清单从“欠 1、2”变为“只欠 2”，仍不能开始。

再完成 2：课程 3 已经什么都不欠，终于可以开始。

整个过程只是在反复做同一件事：

```text
找出不欠任何前置课的课程
-> 完成它
-> 从依赖它的课程清单中划掉它
-> 看是否有新的课程不再欠任何前置课
```

在这一段里，先不要尝试记住“拓扑排序”这个名字。只要确认：**欠账清零的课程可以开始；完成一门课会帮后续课程还掉一笔欠账。**

## 入度：一门课还欠多少前置条件

对每门课程，记录它当前还没有满足的前置课程数量，叫做**入度**。

```text
0 -> 1 -> 2

课程 0：入度 0，没有前置，可以立刻学
课程 1：入度 1，还欠 0
课程 2：入度 1，还欠 1
```

入度为 0 的课程，说明它已经解锁，可以放进队列。

学完一门课程后，它指向的后续课程少了一个前置条件：

```text
学完 0：课程 1 的入度从 1 减为 0，课程 1 解锁
学完 1：课程 2 的入度从 1 减为 0，课程 2 解锁
```

## 邻接表：学完这门课会解锁谁？

输入 `[course, prerequisite]` 的顺序很容易写反。

```text
[1, 0] 的意思是：0 是 1 的前置
正确边方向：0 -> 1
```

因此我们建：

```text
nextCourses[prerequisite].push(course)
indegree[course] += 1
```

这叫**邻接表**。它回答的是：“我现在学完课程 X，哪些课程的前置条件会减少？”

## Kahn 拓扑排序：反复取出已解锁课程

完整流程只有四步：

1. 建邻接表和每门课的入度。
2. 把所有入度为 0 的课程放入队列。
3. 每次取出一门已解锁课程，计入已完成数量；遍历它的后续课程，把后续课程入度减 1。入度变成 0 就入队。
4. 最后若已完成数量等于课程总数，说明全部课程都能解锁；否则剩余课程互相依赖，图中存在环。

## 把刚才的手工过程压缩成三份状态

到写代码时，我们不会保存“欠课程 0”这种文字清单，而是只保存三份足够的信息：

```text
indegree[课程]：这门课还欠几门前置课
nextCourses[课程]：完成这门课后，要通知哪些后续课程
queue：此刻已经不欠任何前置课、现在能开始的课程
```

仍然用刚才的四门课，三份状态刚建立好时是：

```text
indegree = [0, 1, 1, 2]

nextCourses = [
  [1, 2],  // 完成 0，会影响 1、2
  [3],     // 完成 1，会影响 3
  [3],     // 完成 2，会影响 3
  []
]

queue = [0]
```

现在只按下面这个表读，不需要看代码：

| 当前取出谁 | 为什么它能被取出？ | 要通知谁？ | 通知后的变化 | 新队列 |
|---:|---|---|---|---|
| 0 | `indegree[0]` 为 0 | 1、2 | `indegree[1]` 和 `indegree[2]` 都从 1 变 0 | `[1, 2]` |
| 1 | `indegree[1]` 已为 0 | 3 | `indegree[3]` 从 2 变 1，仍不能开始 | `[2]` |
| 2 | `indegree[2]` 已为 0 | 3 | `indegree[3]` 从 1 变 0 | `[3]` |
| 3 | `indegree[3]` 已为 0 | 没有 | 无 | `[]` |

“拓扑排序”只是这个过程的名字。你真正需要会的是：

> 队列中的课程都已经可以开始；取出一门课后，只修改依赖它的后续课程的欠账数量。

## 手工追踪：有环为什么会卡住？

```text
courseCount = 4
prerequisites = [[1, 0], [2, 1], [3, 2], [1, 3]]

边：0 -> 1 -> 2 -> 3 -> 1
```

初始入度：

```text
0: 0
1: 2  （来自 0、3）
2: 1  （来自 1）
3: 1  （来自 2）
```

队列开始只有 `[0]`：

```text
取出 0，完成数 1
0 -> 1，课程 1 入度 2 变 1
```

队列空了，但课程 1、2、3 的入度都仍大于 0。它们形成了环，没有任何一个能先解锁。因此完成数 1 小于 4，返回 `false`。

> 队列提前空了，不是“算法没找到路”，而是剩下的课程都还在等环里的另一个课程。

## 可直接运行的代码

下面使用 `head` 下标读取队列，避免 `shift()` 在每次取队首时移动整个数组。

```js
/**
 * 判断是否能完成全部课程。
 * prerequisites 中 [course, prerequisite] 表示 prerequisite -> course。
 *
 * @param {number} courseCount
 * @param {number[][]} prerequisites
 * @returns {boolean}
 */
function canFinish(courseCount, prerequisites) {
  if (!Number.isInteger(courseCount) || courseCount < 0 || !Array.isArray(prerequisites)) {
    return false;
  }

  const nextCourses = Array.from({ length: courseCount }, () => []);
  const indegree = new Array(courseCount).fill(0);

  for (const prerequisitePair of prerequisites) {
    if (!Array.isArray(prerequisitePair) || prerequisitePair.length !== 2) {
      return false;
    }

    const [course, prerequisite] = prerequisitePair;
    if (
      !Number.isInteger(course) ||
      !Number.isInteger(prerequisite) ||
      course < 0 ||
      course >= courseCount ||
      prerequisite < 0 ||
      prerequisite >= courseCount
    ) {
      return false;
    }

    // 学完 prerequisite 后，course 少一个未完成的前置条件。
    nextCourses[prerequisite].push(course);
    indegree[course] += 1;
  }

  const queue = [];
  for (let course = 0; course < courseCount; course += 1) {
    if (indegree[course] === 0) {
      queue.push(course);
    }
  }

  let completedCount = 0;
  let head = 0;

  while (head < queue.length) {
    const completedCourse = queue[head];
    head += 1;
    completedCount += 1;

    for (const nextCourse of nextCourses[completedCourse]) {
      indegree[nextCourse] -= 1;
      if (indegree[nextCourse] === 0) {
        queue.push(nextCourse);
      }
    }
  }

  return completedCount === courseCount;
}

console.log(canFinish(2, [[1, 0]])); // true：0 -> 1
console.log(canFinish(2, [[1, 0], [0, 1]])); // false：形成环
console.log(canFinish(4, [[1, 0], [2, 0], [3, 1], [3, 2]])); // true
console.log(canFinish(1, [])); // true
console.log(canFinish(2, [[2, 0]])); // false：非法课程编号
```

## 复杂度：`V + E` 不是公式，要分别数顶点和边

在图题中经常写 `O(V + E)`：

```text
V = 顶点数 = courseCount
E = 边数 = prerequisites.length
```

不要直接背，按代码分段数。

### 1. 初始化数组：`O(V)`

```js
Array.from({ length: courseCount }, () => [])
new Array(courseCount).fill(0)
```

都要为每门课程创建一个位置，课程数是 `V`，因此是 `O(V)`。

### 2. 读取所有依赖：`O(E)`

```js
for (const [course, prerequisite] of prerequisites) {
  nextCourses[prerequisite].push(course);
  indegree[course] += 1;
}
```

`prerequisites` 有 `E` 条依赖，每条只做常数操作，因此建图是 `O(E)`。

### 3. 找初始入度为 0 的课程：`O(V)`

遍历每门课程一次，检查它的入度，成本是 `O(V)`。

### 4. BFS 为什么是 `O(V + E)`？

这一步分成两部分：

- **顶点处理次数：** 每门课程的入度一旦变成 0，最多入队一次；从队列取出也最多一次。所以所有课程相关操作最多 `V` 次。
- **边检查次数：** `for (const nextCourse of nextCourses[completedCourse])` 会遍历当前课程的出边。所有课程的出边列表拼起来，正好就是建图时放进去的全部 `E` 条边；每条边只在它的起点课程被取出时检查一次。因此边相关操作总共 `E` 次。

所以 BFS 是 `O(V + E)`，不是 `O(V * E)`。这里没有“每门课都遍历全部依赖”；每门课只遍历属于自己的那一小段出边，所有小段加起来才是全部边。

### 5. 合并总时间

```text
初始化：O(V)
建图：O(E)
找初始队列：O(V)
BFS：O(V + E)

总计：O(V) + O(E) + O(V) + O(V + E)
    = O(3V + 2E)
    = O(V + E)
```

常数 3、2 不影响增长阶，所以最后写 `O(V + E)`。

### 空间复杂度

- 邻接表包含 `V` 个数组槽位和 `E` 条边：`O(V + E)`。
- `indegree` 有 V 个数：`O(V)`。
- 队列最多有 V 门课程：`O(V)`。

相加后仍由 `O(V + E)` 主导，辅助空间是 `O(V + E)`。

## LC200、LC994、LC207 的统一判断

| 题目 | 状态是什么 | 为什么不会重复处理 | 时间复杂度 |
|---|---|---|---|
| LC200 | 网格格子 | 标记为水后不再 DFS | `O(mn)` |
| LC994 | 橘子格子 | 变腐烂后不再入队 | `O(mn)` |
| LC207 | 课程和依赖 | 课程最多入队一次，每条依赖只检查一次 | `O(V + E)` |

> 图搜索的复杂度核心不是“用了 DFS 还是 BFS”，而是“所有状态总共多少个、连接关系总共多少条、每个是否最多处理一次”。
