### 正确答案

**第 1 题：** `numbers = [4, 10, 4, 3, 8, 9]`。

> `lengths[0] = 1`。  
> 10 可以接在前面的 4 后，`lengths[1] = 2`。  
> 第二个 4 不能接第一个 4 或 10 后，`lengths[2] = 1`。  
> 3 前没有更小数，`lengths[3] = 1`。  
> 8 可接在两个 4 或 3 后，最长候选长度为 2，`lengths[4] = 2`。  
> 9 可接在 8 后，`lengths[5] = 3`。最终最大值为 3。

**第 2 题：** 为什么必须固定结尾？

> 只保存“前 i 个数的最长长度”会丢失最后一个值。例如前两个数 `[3,100]` 的最长是 `[3,100]`，但它不能接 4；较短的 `[3]` 却能接 4。`lengths[i]` 固定以 `numbers[i]` 结尾，让我们知道这条序列最后是什么数，才能判断能否接当前数。

**第 3 题：** 为什么是 `O(n^2)`？

> 当前下标为 0 时检查 0 个前驱，为 1 时检查 1 个，直到 n-1 时检查 n-1 个，总数为 `0 + 1 + ... + (n-1) = n(n-1)/2`。常数 1/2 和低阶项不影响增长级别，所以时间是 `O(n^2)`；`lengths` 有 n 个位置，空间是 `O(n)`。

## LC1143：先理解“公共子序列”，再理解二维 DP

给定两个字符串，求它们的最长公共子序列长度。

```text
first = "abcde"
second = "ace"
答案 = 3

公共子序列可以是 "ace"。
```

子序列仍然允许跳过字符，但不能改变原来的相对顺序：

```text
"ace" 是 "abcde" 的子序列：跳过 b、d。
"ace" 也是 "ace" 的子序列。
```

它不是公共子串。公共子串要求连续；本题的 `"ace"` 在 `"abcde"` 中不连续，但仍是合法公共子序列。

## 为什么这次需要两个维度？

LC300 只有一个数组，状态只需说“以第 i 个数结尾”。

LC1143 同时有两个字符串。一个答案取决于：

```text
第一个字符串已经允许使用到哪里？
第二个字符串已经允许使用到哪里？
```

所以我们先定义：

> `common[i][j]`：`first` 的前 i 个字符，与 `second` 的前 j 个字符之间，最长公共子序列的长度。

这里的“前 i 个字符”与 LC198 的“前 i 间房”一样，**i 是数量，不是数组下标**。

| 状态 | 第一个字符串允许使用什么 | 第二个字符串允许使用什么 |
|---|---|---|
| `common[0][j]` | 空字符串 | `second` 的前 j 个字符 |
| `common[i][0]` | `first` 的前 i 个字符 | 空字符串 |
| `common[3][2]` | `first[0..2]` | `second[0..1]` |

只要任意一边是空字符串，就没有公共字符：

```text
common[0][j] = 0
common[i][0] = 0
```

这就是二维表的第 0 行和第 0 列为何全是 0。

## 先手工对齐两个短字符串

先用：

```text
first  = "abcde"
second = "ace"
```

我们不立刻填整张表，只问 `common[1][1]`：

```text
first 的前 1 个字符："a"
second 的前 1 个字符："a"
```

最后两个新加入的字符都是 `a`，相同。显然可以把这个 `a` 放进公共子序列：

```text
common[1][1] = 1
```

再问 `common[2][1]`：

```text
first 的前 2 个字符："ab"
second 的前 1 个字符："a"
最后加入的字符：b 与 a，不同。
```

公共子序列不可能同时把不同的 b 和 a 当作同一个最后字符。此时应该怎么办？

```text
路线 A：暂时不使用 first 新加入的 b，比较 "a" 与 "a"。
路线 B：暂时不使用 second 新加入的 a，比较 "ab" 与空字符串。
```

两条路线的长度分别是：

```text
common[1][1] = 1
common[2][0] = 0
```

取较大值，所以 `common[2][1] = 1`。

## 情况一：两个新加入字符相同

计算 `common[i][j]` 时，新加入的字符是：

```text
first[i - 1]
second[j - 1]
```

因为 i、j 是“前几个字符的数量”，数组下标要减 1。

如果它们相同，例如都是 `c`：

```text
first 的前 i 个字符 = 以前 i-1 个字符的结果 + c
second 的前 j 个字符 = 以前 j-1 个字符的结果 + c
```

前面两段的最长公共子序列长度是 `common[i - 1][j - 1]`；再加上共同的新字符 c：

```text
common[i][j] = common[i - 1][j - 1] + 1
```

注意这里看的是左上角：两个字符串都各自去掉最后一个刚匹配的字符。

## 情况二：两个新加入字符不同

如果 `first[i - 1] !== second[j - 1]`，它们不能同时作为同一个公共子序列的最后字符。

但最长公共子序列可能：

```text
路线 A：不使用 first 的最后一个字符，保留 second 的前 j 个字符。
        长度是 common[i - 1][j]，也就是上方格子。

路线 B：不使用 second 的最后一个字符，保留 first 的前 i 个字符。
        长度是 common[i][j - 1]，也就是左方格子。
```

取更长的一条：

```text
common[i][j] = max(common[i - 1][j], common[i][j - 1])
```

这里不是 `+`：两条路线都在回答同一个格子 `common[i][j]`，一次公共子序列只能采用其中一条对齐方式。

## 为什么必须从左上到右下填？

当前格 `common[i][j]` 只会依赖：

```text
左上：common[i - 1][j - 1]
上方：common[i - 1][j]
左方：common[i][j - 1]
```

这三个格子必须已经存在。因此：

```text
外层 i 从 1 到 first.length
内层 j 从 1 到 second.length
```

按行从左到右填时，左方已经填好；上一行全部更早填完，因此上方和左上也已填好。

> 二维 DP 的遍历顺序不是“惯例”。它由当前格要读取哪个方向的旧状态决定。

## 到这里才看代码：二维数组就是这张表

代码中：

```text
common[i][j]  <=>  表格的第 i 行、第 j 列
first[i - 1]  <=>  本行新加入的字符
second[j - 1] <=>  本列新加入的字符
```

第一次读代码时，只盯住 `if` 的两个分支：

```js
if (first[i - 1] === second[j - 1]) {
  common[i][j] = common[i - 1][j - 1] + 1;
} else {
  common[i][j] = Math.max(common[i - 1][j], common[i][j - 1]);
}
```

它就是上面“新字符相同看左上加 1；不同看上方和左方取最大”的直接翻译。

## 可直接运行的代码

```js
/**
 * 返回两个字符串的最长公共子序列长度。
 * 子序列允许跳过字符，但不能改变字符原有的相对顺序。
 *
 * @param {string} first
 * @param {string} second
 * @returns {number}
 */
function longestCommonSubsequence(first, second) {
  if (typeof first !== 'string' || typeof second !== 'string') {
    return 0;
  }

  const firstLength = first.length;
  const secondLength = second.length;
  const common = Array.from(
    { length: firstLength + 1 },
    () => new Array(secondLength + 1).fill(0),
  );

  for (let i = 1; i <= firstLength; i += 1) {
    for (let j = 1; j <= secondLength; j += 1) {
      if (first[i - 1] === second[j - 1]) {
        // 两边各新增的字符相同，可以共同接在左上角的公共子序列后面。
        common[i][j] = common[i - 1][j - 1] + 1;
      } else {
        // 两边最后字符不同，只能忽略其中一边的最后字符，取更优结果。
        common[i][j] = Math.max(common[i - 1][j], common[i][j - 1]);
      }
    }
  }

  return common[firstLength][secondLength];
}

console.log(longestCommonSubsequence('abcde', 'ace')); // 3
console.log(longestCommonSubsequence('abc', 'abc')); // 3
console.log(longestCommonSubsequence('abc', 'def')); // 0
console.log(longestCommonSubsequence('', 'abc')); // 0
console.log(longestCommonSubsequence('abc', null)); // 0：本地非法输入
```

## 代码逐段对应手工表

| 代码 | 对应含义 |
|---|---|
| `firstLength + 1` 行 | 包含“first 为空”的第 0 行 |
| `secondLength + 1` 列 | 包含“second 为空”的第 0 列 |
| 初始全 0 | 任一边为空时，公共子序列长度是 0 |
| `i` 从 1 开始 | 第 0 行已经是空前缀的初始状态 |
| `j` 从 1 开始 | 第 0 列已经是空前缀的初始状态 |
| `first[i - 1]` | first 前 i 个字符中最后新增的字符 |
| `common[i - 1][j - 1] + 1` | 两边新字符相同，沿左上角公共部分再接一个字符 |
| `max(上方, 左方)` | 两边新字符不同，选择忽略 first 末尾或 second 末尾的更优路线 |

## 复杂度：二维表有多少格？每格做什么？

设：

```text
m = first.length
n = second.length
```

### 第一步：数组创建

`common` 有：

```text
(m + 1) 行
每行 (n + 1) 列
```

总格子数量是：

```text
(m + 1) * (n + 1)
```

创建并填 0 需要访问每个格子，因此是 `O(mn)`。

### 第二步：双层循环

外层 i 从 1 到 m，执行 m 次；内层 j 从 1 到 n，每一行执行 n 次：

```text
m 行 * 每行 n 个状态 = m * n 个状态
```

每个状态只做：一次字符比较，再做一次加 1 或一次 `Math.max`，最后写入一个格子，都是 `O(1)`。

```text
m * n 次 * O(1) = O(mn)
```

### 第三步：合并时间

初始化二维表和填表是先后执行：

```text
O(mn) + O(mn) = O(mn)
```

### 空间复杂度

完整二维表保存 `(m + 1) * (n + 1)` 个数字：

```text
辅助空间 = O(mn)
```

之后可以把二维表压缩成一行或两行，但会让“左上、上方、左方”对应关系更难看清。先稳定掌握完整表格，才能安全优化。

## LC300 与 LC1143：状态为什么从一维变成二维？

| 题目 | 状态需要描述什么范围 | 维度原因 |
|---|---|---|
| LC300 | 数组中以位置 i 结尾的序列 | 只有一个输入数组 |
| LC1143 | first 前 i 个字符与 second 前 j 个字符 | 同时要限制两个字符串的可用范围 |

> 有几个相互独立的输入范围，就常常需要几个状态下标。二维 DP 并不是更神秘的算法，只是同时记录两个前缀范围。
