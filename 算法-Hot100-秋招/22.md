### 正确答案

**第 1 题：** 为什么 `ways[6] = ways[5] + ways[4]`？

> 到第 6 阶的最后一步要么走 1 阶，前面必须已经到第 5 阶，对应 `ways[5]` 种；要么走 2 阶，前面必须已经到第 4 阶，对应 `ways[4]` 种。最后一步分别为 1 与 2，两组不能是同一条走法；又覆盖了所有合法最后一步，所以相加。

**第 2 题：** 初始值与循环范围。

> `ways[0] = 1`、`ways[1] = 1` 是已知起点。循环从 `step = 2` 到目标 `n`，因为从 2 开始才能安全使用 `ways[step - 1]` 与 `ways[step - 2]`。下标 0、1 没有两个更小的状态可供转移。

**第 3 题：** 时间复杂度。

> 数组有 `n + 1` 个位置，初始化是 `O(n)`；循环运行从 2 到 n 的约 n 次，每次只做常数次读取、加法和写入，也是 `O(n)`。先后两段相加仍为 `O(n)`。

## LC198：这次不是数方案，而是在两个合法选择中取最大值

一排房屋中，第 i 间房的钱为 `amounts[i]`。不能偷相邻的两间房，求最多能偷到多少钱。

```text
amounts = [2, 7, 9, 3, 1]
答案 = 12

一种最优选择：偷 2、9、1
```

LC70 问“有多少种走法”，所以不同来源的方案要相加。LC198 问“最多多少钱”，所以你必须在多个合法选择中选更大的一个。

> 遇到“最多 / 最少 / 最大 / 最长”这类词，通常不能直接把分支相加；先比较每个分支代表的结果，再取 `max` 或 `min`。

## 暂时不看代码：只看最后一间房偷不偷

先只考虑前三间房：

```text
金额：[2, 7, 9]
编号： 0  1  2
```

我们想求“只看前 3 间房时，最多能偷多少”。最后一间房是编号 2、金额 9 的房子。

它只有两个互斥选择：

```text
选择 A：不偷编号 2 的房子。
        那么最大金额就是“只看前 2 间房时”的最大金额。

选择 B：偷编号 2 的房子。
        因为不能偷相邻房，编号 1 不能偷；
        只能加上“只看前 1 间房时”的最大金额，再加 9。
```

手工算：

```text
不偷 9：前两间 [2, 7] 的最大金额是 7。
偷 9：前一间可看的范围只剩 [2]，最大金额 2，再加 9，得到 11。

取较大值：11。
```

这就是本题全部转移逻辑：

> 对当前房，要么跳过它，沿用前一段的最优金额；要么偷它，接上不能相邻的前两段最优金额。两者取最大。

## 先定义状态：`best[i]` 不要理解错下标

这篇使用一个很稳的定义：

```text
best[i] = 只考虑 amounts 的前 i 间房时，最多能偷到的钱。
```

注意“前 i 间”不是“下标 i 的房”。它们的对应关系是：

| `i` | `best[i]` 考虑的房屋下标 | 含义 |
|---:|---|---|
| 0 | 没有房屋 | 最大金额 0 |
| 1 | `[0]` | 只考虑第 0 间房 |
| 2 | `[0, 1]` | 考虑第 0、1 间房 |
| 3 | `[0, 1, 2]` | 考虑第 0 到第 2 间房 |

采用这个定义的好处是边界很自然：

```text
best[0] = 0  // 没有房子，拿不到钱
best[1] = amounts[0]  // 只有一间房，只能偷它
```

## 用最后一间房推导转移式

现在求 `best[i]`，也就是考虑前 i 间房。当前要决定的是第 i-1 间房，因为数组下标从 0 开始。

```text
不偷第 i-1 间：金额是 best[i - 1]
偷第 i-1 间：金额是 best[i - 2] + amounts[i - 1]
```

所以：

```text
best[i] = max(
  best[i - 1],
  best[i - 2] + amounts[i - 1]
)
```

这里是 `max`，不是 `+`：两种情况都在描述“同一个问题 best[i] 的两种互斥决策”，你只能选择其中一种实施。

## 手工填完整张表

继续使用：

```text
amounts = [2, 7, 9, 3, 1]
```

| i | 当前新加入考虑的房子 | 不偷当前房 | 偷当前房 | `best[i]` |
|---:|---|---:|---:|---:|
| 0 | 无 | 无 | 无 | 0 |
| 1 | 下标 0，金额 2 | 无 | 2 | 2 |
| 2 | 下标 1，金额 7 | `best[1] = 2` | `best[0] + 7 = 7` | 7 |
| 3 | 下标 2，金额 9 | `best[2] = 7` | `best[1] + 9 = 11` | 11 |
| 4 | 下标 3，金额 3 | `best[3] = 11` | `best[2] + 3 = 10` | 11 |
| 5 | 下标 4，金额 1 | `best[4] = 11` | `best[3] + 1 = 12` | 12 |

读表时只问一个问题：当前房偷不偷，哪边钱更多？

```text
第 4 间房金额只有 3。
偷它会失去相邻的第 3 间房带来的最优组合，结果只有 10。
不偷它可以保留已有的 11。
所以当前房不一定要偷，即使它里面有钱。
```

## 为什么从小到大填表？

计算 `best[i]` 时，需要已经算好的：

```text
best[i - 1]
best[i - 2]
```

所以必须按 i 从小到大填：

```text
best[0]、best[1] 已知
再算 best[2]
再算 best[3]
...
```

遍历顺序来自依赖关系，和 LC70 完全一样；只是 LC70 的两个来源相加，而 LC198 的两个来源取最大值。

代码中的 `best` 就是上一节手工表。第一次读代码只盯住这一行：

```js
best[houseCount] = Math.max(
  best[houseCount - 1],

);
```

把变量换回人话：

```text
前 i 间的最优金额 = max(不偷当前房，偷当前房)
```

## 可直接运行的代码

```js
/**
 * 返回不能偷相邻房屋时可获得的最大金额。
 *
 * @param {number[]} amounts
 * @returns {number}
 */
function rob(amounts) {
  if (!Array.isArray(amounts) || amounts.some((amount) => !Number.isFinite(amount) || amount < 0)) {
    return 0;
  }

  const houseCount = amounts.length;
  if (houseCount === 0) {
    return 0;
  }

  const best = new Array(houseCount + 1).fill(0);
  best[0] = 0;
  best[1] = amounts[0];

  for (let count = 2; count <= houseCount; count += 1) {
    const skipCurrentHouse = best[count - 1];
    const robCurrentHouse = best[count - 2] + amounts[count - 1];

    // 当前房只有“偷”或“不偷”两种互斥决策，保留金额较大的那种。
    best[count] = Math.max(skipCurrentHouse, robCurrentHouse);
  }

  return best[houseCount];
}

console.log(rob([2, 7, 9, 3, 1])); // 12
console.log(rob([2, 1, 1, 2])); // 4
console.log(rob([5])); // 5
console.log(rob([])); // 0
console.log(rob([2, -1])); // 0：本地非法输入
```

## 代码逐段对应手工表

| 代码 | 对应含义 |
|---|---|
| `houseCount = amounts.length` | 一共有 n 间房 |
| `best = new Array(houseCount + 1)` | 准备保存“前 0 间”到“前 n 间”的最优金额 |
| `best[0] = 0` | 没房可偷，金额为 0 |
| `best[1] = amounts[0]` | 只有第一间房，只能偷它 |
| `skipCurrentHouse` | 不偷当前新加入的房，保留前 i-1 间最优金额 |
| `robCurrentHouse` | 偷当前房，只能接上前 i-2 间最优金额 |
| `Math.max(...)` | 两条路线只能选一条，取更大金额 |

## 复杂度：继续按“输入规模 -> 循环 -> 单次工作”计算

设：

```text
n = amounts.length = 房屋数量
```

### 时间复杂度

数组 `best` 有 `n + 1` 个位置，创建并填充是 `O(n)`。

循环的 `count` 依次为：

```text
2、3、4、...、n
```

共 `n - 1` 次。每轮只做：

```text
读取两个 best 值
读取一个金额
一次加法
一次 Math.max（比较两个数）
一次写入
```

这些次数不随 n 增加，所以每轮是 `O(1)`：

```text
(n - 1) * O(1) = O(n)
```

初始化 `O(n)` 和循环 `O(n)` 先后发生：

```text
O(n) + O(n) = O(n)
```

### 空间复杂度

`best` 保存 `n + 1` 个数，因此辅助空间是 `O(n)`。

和 LC70 一样，当前结果只依赖前两个 `best` 值，之后可以压缩成两个变量得到 `O(1)` 空间。先把数组状态表写稳，再做优化。

## LC70 与 LC198：同样是 DP，为什么一个加、一个取最大？

| 题目 | 状态问的是什么 | 最后一步的分支如何合并 |
|---|---|---|
| LC70 爬楼梯 | 一共有多少种合法走法 | 两组走法都要计数，`+` |
| LC198 打家劫舍 | 最多能获得多少钱 | 两种决策只能选一种，`max` |

> 先问状态要的是“数量”还是“最优值”，再决定分支是相加、取最大还是取最小。不要从公式形状猜题型。
