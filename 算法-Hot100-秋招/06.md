## LC560：这题为什么不能直接套 LC209？

LC560「和为 K 的子数组」：给定整数数组 `numbers` 和整数 `target`，求和恰好等于 `target` 的**连续子数组**数量。

```text
numbers = [1, 1, 1]
target = 2
答案 = 2
原因：[1, 1] 出现了两次，分别从下标 0 和下标 1 开始。
```

这题看起来像 LC209，但有两个本质不同：

| LC209 | LC560 |
|---|---|
| 求最短长度 | 求满足条件的子数组数量 |
| 数组全为正整数 | 数组可以有负数和 0 |
| 总和至少为 target | 总和恰好等于 target |

因为 LC560 可以出现负数，窗口和不再单调：右端加入一个数，和可能变大、变小或不变。上一章已经见过，这时不能再靠左右指针决定缩不缩。

我们要换一种问题视角：不再维护一个窗口，而是记录“从开头走到当前位置时，累计和是多少”。

## 什么是前缀和？

**前缀和**就是“从下标 0 一直加到当前位置”的和。

对 `numbers = [1, 2, 3]`：

| 位置 | 数字 | 到这里为止的前缀和 |
|---:|---:|---:|
| 开始前 | - | 0 |
| 0 | 1 | 1 |
| 1 | 2 | 3 |
| 2 | 3 | 6 |

如果一段连续子数组从 `left` 到 `right`，它的和可以这样得到：

```text
numbers[left..right] 的和
= 到 right 的前缀和 - 到 left 前一个位置的前缀和
```

例如 `[2, 3]` 的和：

```text
到下标 2 的前缀和 6 - 到下标 0 的前缀和 1 = 5
```

## 把“区间和等于 target”改成找历史状态

假设当前走到 `right`，当前前缀和是 `currentPrefixSum`。我们希望某段连续子数组的和等于 `target`：

```text
currentPrefixSum - 之前某一刻的前缀和 = target
```

移项后：

```text
之前某一刻的前缀和 = currentPrefixSum - target
```

这就是本题唯一需要记住的公式：

> 当前前缀和是 `sum` 时，去找历史上出现过多少次 `sum - target`。

每找到一次历史前缀和 `sum - target`，就对应一个“以当前下标结尾、和为 target”的连续子数组。

所以 `Map` 的含义是：

```text
键：某个前缀和。
值：这个前缀和以前出现过几次。
```

注意：值是**次数**，不是下标。因为同一个前缀和出现多次时，会产生多个不同起点的合法子数组，必须全部计入答案。

## 手工走一次：`[1, 1, 1]`，目标 2

开始前先放入：`0 -> 1`，含义是“还没有选择任何数字时，前缀和 0 出现过一次”。后面会解释为什么这是必须的。

| 当前数字 | 当前前缀和 | 要找的历史前缀和 `sum - target` | 找到几次 | 答案累加后 | 记录当前前缀和后 |
|---:|---:|---:|---:|---:|---|
| 1 | 1 | -1 | 0 | 0 | `0:1, 1:1` |
| 1 | 2 | 0 | 1 | 1 | `0:1, 1:1, 2:1` |
| 1 | 3 | 1 | 1 | 2 | `0:1, 1:1, 2:1, 3:1` |

第二个 1 时，找到了历史前缀和 0，对应子数组 `[1, 1]`（下标 0 到 1）。

第三个 1 时，找到了历史前缀和 1，对应子数组 `[1, 1]`（下标 1 到 2）。

答案一共是 2。

## 为什么一开始必须放入 `0 -> 1`？

考虑：

```text
numbers = [3]
target = 3
```

读到第一个 3 时，当前前缀和为 3。根据公式，要找 `3 - 3 = 0`。

如果 `Map` 里没有预先放 `0 -> 1`，代码会认为不存在答案；但 `[3]` 明明就是一个从下标 0 开始的合法子数组。

所以 `0 -> 1` 不是特殊技巧，它代表一种真实状态：**数组开始前，前缀和 0 已经出现过一次。**

## 顺序：先查，再记录

每轮的顺序必须是：

```text
1. 加入当前数字，得到当前前缀和。
2. 查询历史上出现过多少次 currentPrefixSum - target。
3. 再把当前前缀和的出现次数加 1。
```

用 `numbers = [0]`、`target = 0` 验证：

```text
开始：0 -> 1。
读到 0：当前前缀和仍是 0。
先查：历史 0 出现 1 次，答案加 1，对应子数组 [0]。
再存：0 的次数变为 2。
```

若先存再查，0 的次数先变为 2，再加到答案，会把同一个子数组算两次。

## 可直接运行的代码

```js
/**
 * 返回和恰好等于 target 的连续子数组数量。
 * numbers 可以包含负数、0 和正数。
 *
 * @param {number[]} numbers
 * @param {number} target
 * @returns {number}
 */
function subarraySum(numbers, target) {
  if (!Array.isArray(numbers) || !Number.isFinite(target)) {
    return 0;
  }
  if (numbers.some((number) => !Number.isFinite(number))) {
    return 0;
  }

  const countByPrefixSum = new Map();
  countByPrefixSum.set(0, 1);

  let currentPrefixSum = 0;
  let subarrayCount = 0;

  for (const number of numbers) {
    currentPrefixSum += number;

    const neededPrefixSum = currentPrefixSum - target;
    subarrayCount += countByPrefixSum.get(neededPrefixSum) ?? 0;

    // 当前前缀和将成为后续位置可查询的历史状态。
    countByPrefixSum.set(
      currentPrefixSum,
      (countByPrefixSum.get(currentPrefixSum) ?? 0) + 1,
    );
  }

  return subarrayCount;
}

console.log(subarraySum([1, 1, 1], 2)); // 2
console.log(subarraySum([1, 2, 3], 3)); // 2
console.log(subarraySum([1, -1, 0], 0)); // 3
console.log(subarraySum([3], 3)); // 1
```

## 一句话区分 LC1、LC49、LC560 的 `Map`

| 题目 | 键 | 值 | 因为后续要做什么 |
|---|---|---|---|
| LC1 | 已出现的数字 | 下标 | 找到搭档后返回位置 |
| LC49 | 分类身份证 | 字符串数组 | 把同类字符串追加进同一组 |
| LC560 | 历史前缀和 | 出现次数 | 一次历史状态对应一个合法起点，需要全部累计 |

这张表不需要死背。每次使用 `Map` 前，先问自己：**我后续要从这个键拿到什么？** 答案就是值应保存的内容。

## 复杂度

只遍历数组一次，每轮对 `Map` 查询和更新各一次：

```text
时间复杂度：O(n)
空间复杂度：O(n)
```

与滑动窗口不同，LC560 不依赖数组中的数字为正数。它只利用前缀和的数学关系，因此负数和 0 都能正确处理。
