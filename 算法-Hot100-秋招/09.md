## LC15：从“找两个数”升级为“找三元组”

LC15「三数之和」：给你一个整数数组，找出所有三个数之和为 0 的**不重复三元组**。

```text
输入：[-1, 0, 1, 2, -1, -4]
输出：[[-1, -1, 2], [-1, 0, 1]]
```

要求里有三个重点：

- 必须选三个不同位置的元素。
- 三个数的和恰好为 0。
- 结果中不能出现重复三元组。

如果直接写三层循环，能找出答案，但时间复杂度是 `O(n^3)`，而且重复值会制造大量重复结果。

这道题的主线是：

```text
排序
固定第一个数
在右侧用相向双指针找剩下两个数
遇到重复值时跳过
```

## 为什么先排序？

排序不是为了让结果好看，而是为双指针提供“移动方向”。

排序后：

```text
[-4, -1, -1, 0, 1, 2]
```

假设第一个数固定为 `fixedNumber = -1`，现在要在它右边找两个数，使：

```text
leftNumber + rightNumber = 1
```

如果当前三个数的和太小，例如：

```text
-1 + -1 + 2 = 0  // 刚好
```

再换一个：

```text
-1 + -1 + 1 = -1 // 太小
```

因为数组已排序，右移 `left` 才可能让中间数变大、使总和增加；左移 `right` 只会让右边数变小，更不可能补回“总和太小”。

同理，若总和太大，只能左移 `right`。

> 排序后，和太小就移动左指针让和变大；和太大就移动右指针让和变小。

## 第一步：固定一个数，把三数问题降为两数问题

外层循环依次选第一个数，记为 `fixedIndex`：

```text
fixedNumber = sortedNumbers[fixedIndex]
```

然后只在它右侧找另外两个数：

```text
left = fixedIndex + 1
right = 最后一个下标
```

目标不再是找两个数加起来等于 0，而是：

```text
sortedNumbers[left] + sortedNumbers[right] = -fixedNumber
```

这和 LC1 的“当前数还差一个搭档”是同一种拆解：先固定已知部分，再计算剩余部分需要满足什么。

## 手工走一遍 `[-1, 0, 1, 2, -1, -4]`

先排序：

```text
[-4, -1, -1, 0, 1, 2]
```

### 固定 `-4`

```text
left = -1，right = 2，总和 = -4 + -1 + 2 = -3，太小。
left 右移。
之后总和仍不可能达到 0，最终结束。
```

### 固定第一个 `-1`

```text
left = 第二个 -1，right = 2。
总和 = -1 + -1 + 2 = 0，记录 [-1, -1, 2]。
left 右移，right 左移。

left = 0，right = 1。
总和 = -1 + 0 + 1 = 0，记录 [-1, 0, 1]。
left 右移，right 左移，两个指针相遇，结束。
```

### 固定第二个 `-1` 时为什么直接跳过？

它和前一个固定数的值相同，后续可选范围也只会更小。前一个 `-1` 已经尝试过所有右侧组合；再做一次只会生成相同三元组。

因此固定数去重的规则是：

```js
if (fixedIndex > 0 && sortedNumbers[fixedIndex] === sortedNumbers[fixedIndex - 1]) {
  continue;
}
```

## 找到答案后，为什么两端都要跳过重复值？

例如已经找到：

```text
[-1, -1, 2]
```

如果左边下一个数仍是 `-1`，或右边下一个数仍是 2，再次组合得到的值仍是 `[-1, -1, 2]`，属于重复答案。

稳定的处理顺序是：

```text
记录三元组。
left 向右移动一格，right 向左移动一格。
继续跳过与刚才相同的 left 值和 right 值。
```

这样不会跳过新解：相同数值只能构成相同三元组；真正不同的三元组一定要使用至少一个不同数值。

## 可直接运行的代码

```js
/**
 * 返回所有和为 0 的不重复三元组。
 *
 * @param {number[]} numbers
 * @returns {number[][]}
 */
function threeSum(numbers) {
  if (!Array.isArray(numbers) || numbers.length < 3) {
    return [];
  }
  if (numbers.some((number) => !Number.isFinite(number))) {
    return [];
  }

  // 复制后排序，避免修改调用方传入的原数组。
  const sortedNumbers = [...numbers].sort((first, second) => first - second);
  const triples = [];

  for (let fixedIndex = 0; fixedIndex < sortedNumbers.length - 2; fixedIndex += 1) {
    const fixedNumber = sortedNumbers[fixedIndex];

    // 固定数重复时，后续组合一定已由前一个相同数处理过。
    if (fixedIndex > 0 && fixedNumber === sortedNumbers[fixedIndex - 1]) {
      continue;
    }

    let left = fixedIndex + 1;
    let right = sortedNumbers.length - 1;

    while (left < right) {
      const total = fixedNumber + sortedNumbers[left] + sortedNumbers[right];

      if (total < 0) {
        // 数组有序：右移 left 才可能让总和变大。
        left += 1;
      } else if (total > 0) {
        // 数组有序：左移 right 才可能让总和变小。
        right -= 1;
      } else {
        triples.push([fixedNumber, sortedNumbers[left], sortedNumbers[right]]);
        left += 1;
        right -= 1;

        // 跳过相同数值，避免收集重复三元组。
        while (left < right && sortedNumbers[left] === sortedNumbers[left - 1]) {
          left += 1;
        }
        while (left < right && sortedNumbers[right] === sortedNumbers[right + 1]) {
          right -= 1;
        }
      }
    }
  }

  return triples;
}

console.log(threeSum([-1, 0, 1, 2, -1, -4]));
// [[-1, -1, 2], [-1, 0, 1]]

console.log(threeSum([0, 1, 1])); // []
console.log(threeSum([0, 0, 0, 0])); // [[0, 0, 0]]
console.log(threeSum([])); // []
```

## 最容易犯的四类错误

### 1. 忘了数值排序比较器

JavaScript 的默认 `sort()` 会按字符串顺序排序：

```js
[2, 10, 1].sort(); // [1, 10, 2]
```

数值排序必须写：

```js
numbers.sort((first, second) => first - second);
```

### 2. 只固定数去重，左右指针不去重

输入 `[0, 0, 0, 0]` 时，若找到一个 `[0, 0, 0]` 后不跳过重复左右值，可能重复加入相同答案。

### 3. 总和为 0 后只移动一个指针

找到三元组后，当前这两个位置已经用过，应让 `left` 和 `right` 同时向中间移动，再跳过重复值。只移动一边会导致重复或漏掉对称位置。

### 4. 未排序就按总和移动指针

“总和太小 -> `left += 1`”只有在数组有序时才成立。未排序时，右移可能遇到更小的数，移动方向没有依据。
